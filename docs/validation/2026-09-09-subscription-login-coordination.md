# 订阅登录管理与协调验证

2026-09-09，Refs #11；主负责开发者 @xiaoxuanli-a，Codex 作者自查。代码基线 11b8cc7，后续本切片实现管理租约与登录协调；没有独立审阅、实际账号登录或远端发布。

## 依据与实现

按用户要求先核对 Blackbox 的 credentials.py：登录在管理占用内进行，Harness 执行结束后仍检查凭据存在；不能仅凭退出 0 报告成功。旧代码由凭据模块直接组合 Docker 交互登录，本次保留管理边界，通过独立受信驱动端口隔离命令、环境和用户交互。

新 CredentialManagementStore/Lease 在凭据不存在时也可取得同一 credentialRef 的跨进程锁。configure 使用原 generation/revision 或未配置状态核对，允许明确的管理替换，仍验证 codec 格式并原子保存。原 FileCredentialStore.configure 复用此机制；执行租约的刷新身份限制不变。

SubscriptionLoginCoordinator 先取得管理占用，再消费登录驱动。只有原执行成功、停止确认及资源移除后，才读取和保存私有材料；删除临时材料后释放管理占用。遇到异常、不可靠执行事实或清理失败，返回保留能力的 attempt。retryCleanup 不重新登录、不重复保存、不升级原失败。公开结果仅含本地状态、元数据与静态诊断，不复制原始 Runner 记录或私有材料。

当前只有协调接口和存储实现，没有 Codex/Claude 原生登录驱动或 auth login 命令。版本预检、受控网络、登录交互、私有材料安全读取与实际 Harness 登录的联合验证仍须在下一切片接通，不能将本记录当作完整登录验收。

## 验证结果

macOS arm64 / Node 26；全部凭据为合成值。

- 管理租约：未配置时排他占用；其他执行/管理/删除失败；显式替换与运行刷新分离；调用方身份变动不影响选定身份；串行提交递增 revision；释放后不可配置；格式错误、外部 generation/revision 变化及从未配置变为已配置均不覆盖。
- 真实子进程：首次登录尚无凭据时，另一进程也无法配置或执行；持有者 SIGKILL 后锁仍保留，未根据进程死亡自动接管。无旧容器恢复声明。
- 驱动替身：首次登录成功、失败/取消、非法材料和读取错误；保存前取消；停止未知和错误资源不能释放；保存成功但临时清理失败后重试不重复运行或保存；驱动抛出异常仍有清理句柄，恢复不把未知执行变成成功。
- 首轮完整检查 232 项通过；随后增加畸形执行证据校验。
- 自查补充管理锁释放失败的反例：工作区已清理时，旧重试路径再次调用 recover，导致无法完成释放。先核对 Blackbox 的管理独占、finally 释放实现及 f1f9935 容量改动、释放/异常测试，再用故障注入复现本项目 pending_cleanup 不结束。修正为私有清理已完成时仅重试管理锁；反例由失败变为通过，不重新登录或保存。
- 修正后重新执行完整 `npm run check`（包含最终两个反例），结果见下文最终检查；三个既有镜像及 Docker/egress 均启用，覆盖原凭据、CLI、Workflow 及三 Harness。

正常文件格式拒绝、失败执行和保存前取消的测试确认旧材料不变；存储提交期间的 IO 异常可能发生在原子替换之后，不能仅凭失败状态推断磁盘未改变。公开状态保持本地检查语义，远端认证仍为 unknown。
