# DeepSeek 私有会话采集与原生完成证据

关联 #10/#11/#12、[Harness 决定](../../.agents/decisions/product/README.md#p-20260909-harness-adapter) 与 [Runner 决定](../../.agents/decisions/product/README.md#p-20260909-runner-lifecycle)。这是内部采集和解析切片，尚未提供可执行 DeepSeek Harness。

## 依据与范围

先核对 Blackbox Agent Flow 5610d1b / v0.1.22 的 DeepSeek 定义、audit 格式、完成/输出修复和探针说明。其原生会话位于独立状态目录，不能把未经处理的日志放入业务产物；没有可直接迁用的本项目终态解析器。随后读取实际安装的 dsh 0.1.1-rc.2 的会话持久化格式、事件/消息类型及 DeepSeek 用量映射，并用真实 CLI 生成合成会话核对字段。

使用既有镜像 sha256:a92f35565532db0e3c9ace1454754a0232a35ff413d31ebe3c7a90e7ae78916b / Node 22.23.2。测试在断网容器中使用合成凭据和本地模型响应，没有真实账号、远程模型调用或学生材料。

## 当前行为

容器应用增加可信的 post-exit 采集函数，从固定 /task/state/deepseek/sessions 的原生 project/session/session.jsonl 布局选择唯一记录。调用方必须先确认 CLI 和工具进程停止；函数不负责停止它们。拒绝链接、硬链接、非预期文件布局、混合压缩、多个会话、过多目录项和超过 16 MiB 的记录；比较打开后的文件大小和时间属性以发现读取期间变化。原始字节独占写入固定私有记录，已有目标不会被覆盖，失败清除本次半成品。

Runner 通过既有 recordFiles 读取该记录。实际集成发现旧规则限定每项 1 MiB，现改为最多 16 项共享 16 MiB 总声明预算，单项可使用全部预算；保持原总量，不增加 Harness 特例。超过总预算仍在准备阶段失败。

宿主内部 interpretDeepseekSession 不依赖容器 SDK，也不把 stdout 当协议。它核对版本、Runner 身份、退出与清理事实、完整记录和原始字节数；要求存储版本 0、固定 cwd、无种子/委派/预设的全新顶层会话。直接用户消息必须与本次 prompt 完全一致。连续事件序号、turn/step 边界、模型来源、工具声明/执行/结果、最终 stop 与 completed 终态共同提供完成证据。工具自身返回错误可以交由 Agent 处理，但缺失工具结果、截断、异常终态或未闭合步骤不能成功。

只累计 assistant/message.usage，忽略流式 chunk 中同一份会计数据。根据 rc.2 的实际 DeepSeek 映射把缓存读取加回总输入；未报告的缓存/推理字段保持 null，整步缺失用量会使相应总量未知。拒绝负数、非整数和溢出。对外仅投影生命周期、工具名称及脱敏模型文字，未知必需事件失败，显式可忽略的未知事件只保留脱敏类型；种子、委派等已知不支持事件不能用 ignorable 标记绕过。

## 已执行验证

- 同一真实 CLI 的 15 次工具操作产生 16 个模型步骤；原生私有日志经采集函数和 Runner 进入解析器，字节与实际原始日志一致。完整完成证据通过，用量恰为输入 160 / 输出 32，未把流式计数加倍。原有文件/搜索/进程隔离断言继续通过。
- 真实容器采集接口验证原字节、0600 权限、拒绝已有目标覆盖、无记录、多记录、压缩日志、符号/硬链接、目录链接、16 MiB 超限和目录项上限；失败后无新目标，私有源标记不变。
- 六组解析测试覆盖 Runner/版本/记录不完整、任务/会话错配、非法编码和序号、逐项移除或重复关键事件、各种失败终态、工具关联和参数错配、未知事件、用量缺失/非法/溢出及脱敏失败。模型文字或伪造的任务 JSON 不承担终态权限。
- Docker 实际采集 2 MiB 原始记录成功；单项超出 16 MiB 或多项合计超额均在启动前拒绝。对外诊断沿用 Runner 的 PREPARE_FAILED，不暴露内部异常文本。

最终完整 npm run check 启用 Docker、受控联网及三个既有 Harness 镜像：184 项通过、0 失败、0 跳过，包含依赖边界、构建、测试类型检查和全部测试。作者验证，无独立评审、远端 CI 或发布。
