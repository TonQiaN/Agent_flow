## Blackbox 已解决的问题与新实现差异

本次先查参考项目 v0.1.22 / 5610d1b 的工作树及修复提交 f508c78，再核对新实现；参考工作树未提交内容不当作已发布事实。

- `credential_recovery.py` 与 `test_credential_recovery.py` 已处理原地截断写导致的 JSON 损坏：保存可解析快照，健康文件不回滚，没有快照不恢复，未知格式不强修。快照可解析不等于远端 token 有效。
- 新 `FileCredentialStore` 使用原子替换及 revision/generation；执行工作副本损坏不会覆盖源文件。这已预防一种故障，但不等于实现了源存储损坏后的备份恢复。
- 旧 `logout_profile` 删除 live 文件，当前看到的该函数没有同步移除 `.last-good`；旧恢复函数也允许 live 缺失时从快照恢复。因此不能原样搬运并宣称满足本项目“删除后不复活”。新的备份、删除及恢复协议必须一起验证。
- 旧 `api_keys.py` 的 getpass/终端检查，以及 `credentials.py` 的管理租约和登录协调可作为入口参考。新项目已有受控文件来源；不能照搬旧函数注释中“无文件来源”的过时描述，也不能把 Python 模块作为 TypeScript 运行依赖。
