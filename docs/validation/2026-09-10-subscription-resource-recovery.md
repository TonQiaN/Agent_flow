# 订阅资源与完整批卷恢复验证

2026-09-10（悉尼），主责 @xiaoxuanli-a，Codex 实现与作者自查，关联 [Issue #13](https://github.com/TonQiaN/Agent_flow/issues/13)。未进行独立审阅、远端发布或真实账号调用。

## 预检与实现

基线 39444c8。先核对 Blackbox v0.1.22 / 5610d1b 的 credential_leases.py、credential_recovery.py、runners.py 订阅独占及结束后保存刷新路径，以及 f508c78、f1f9935 的修复历史。旧 flock 随进程退出释放，不能直接证明当前 Docker 子执行已停止；本项目保留资源归属，再经共同 Runner 停止后收尾。实现前修订唯一持久化决定，未改变用户 contract、固定目录、路由或返修策略。

FileCredentialStore 增加资源归属和耐久收尾结果。SubscriptionResourceBinding 延后取得来源至已记录的 prepare，恢复只读绑定直到共同 Runner release。Codex/Claude 使用同一实现；Driver 不再把订阅取得登记成无归属的独立操作阶段。引擎没有订阅分支。PrivateStateBinding 恢复额外接收后端已核对的 stateDirectory，环境密钥绑定继续不读取来源。

## 检查与故障案例

新增五项普通测试覆盖：新实例收尾保存刷新、迟到读取/再次取得拒绝、重复恢复不回滚新配置或复活删除；取得前恢复封存；无效刷新保留原来源；未知锁和操作临界区保留阻塞；加载不访问来源；停止前不释放；来源版本冲突和损坏收尾记录拒绝。

新增四项真实 Docker/SQLite/独立进程测试：Codex、Claude 各在 Agent 实际运行及发布前 SIGKILL 宿主。使用既有协议替身，容器先刷新合成 token，再交付批卷候选。实际 inspect 确认旧容器 running，来源此时仍 busy；删除原输入及中间临时目录后，完整严格加载不取得凭据。恢复保留先前接纳步骤，以同一 NodeTask 的 Attempt 2 继续，只产生一条本地发布记录，评分为 5/7；来源刷新至 revision 2，未因正常刷新触发定义漂移。发布前中断后重新配置合成凭据，恢复不调用 Agent、不覆盖该配置。

第一轮六项 Docker 检查五通过：四项新增完整恢复及 Codex 普通组合通过；Claude 普通组合发现首次准备前拒绝的凭据被误记为 failed。回查 Blackbox 的格式失败边界及既有 Binding 后，区分当前宿主确认未准备与恢复缺失副本，恢复正确的 not_prepared 状态，没有修改既有断言或放宽认证校验。首次类型检查另指出环境绑定测试仍使用旧参数形状，按后端实际 stateDirectory 补齐。首次普通测试的四项代理监听失败为沙箱 EPERM，在既有授权下开放本机测试端口后复验。

最终结果见本记录末尾。测试包含普通回归、Codex/Claude 普通组合、不可变 API key 恢复，以及 DeepSeek 协议替身的原完整 Tutor 回归；不存在本轮官方模型调用。

## 局限

替身模拟协议及凭据刷新，不证明真实官方登录、远端 token 有效性、评分质量或真实学生卷/PDF。没有机器重启或硬件断电实验。短源操作临界区中 SIGKILL 的自动接管未实现，保留锁并明确阻塞；不把 PID 死亡当作可解除依据。PR 审阅/合并与 Issue 关闭尚未完成。
