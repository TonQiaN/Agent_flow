# Effect 持久日志与进程中断验证

本轮补齐 Issue #13 的独立逻辑操作日志。先对照 Blackbox v0.1.22 / 5610d1b 的 Effect 记录、输入一致性和回执提交后中断测试，采用提交占位后调用、回执提交后接纳的边界，不复用旧实现的整 Run 运行模型。

## 验收优先级核对

Issue #13 明确要求耐久输入/输出、节点边界恢复和 Effect 回执/未知操作处理，没有要求首版通用临时文件 GC。此前续接记录把剩余清理优化当成优先前置，偏离了这一重点。本轮已纠正已有任务的续接优先级：保留临时文件局限，先补 Effect 与其他明确恢复验收；没有新增用户需求、通用 GC 平台或发布权限。

## 实现与边界

EffectRecordStore 是引擎操作日志端口，SqliteEffectRecordStore 复用现有 SQLite 事务/CAS及耐久配置，独立命名空间身份首次提交后保持。EffectExecutor 的可选第四参数安装该能力，固定方法和非秘密身份。逻辑 key、Component/实现、业务身份、目标和规范化 JSON 输入关联；授权仍按本次 Run/NodeTask/Attempt 签发并一次消费。

无记录时唯一 create 提交 pending，确认后才 apply；合法收据通过 contract 后 CAS 写 applied，提交确认后返回 accepted。重复并发只能有一个 create 成功，其他执行不调用服务。新进程遇到 applied 会核对完整上下文及 contract，然后返回 already-applied；pending 或提交不明一律 unknown，没有恢复旧授权、自动删除占位或重发能力。dry-run 不碰持久日志。

## 已执行检查

本地 Node 26，315 项常规测试通过，约 7.53 秒，0 失败、取消、跳过；包含原 Tutor 合成批卷、Gate/返修和模拟发布回归。定向 Effect/日志 17 项通过，约 1.56 秒。未运行真实模型或业务服务；副作用目标是测试拥有的文件，写入后 fsync，以便独立于被杀宿主保留观察结果。

新增 10 项测试覆盖：

- 四个真实 SIGKILL 边界：占位前、占位已提交、外部模拟写入后、回执提交后。新进程只在完全未占位时执行；两个 pending 边界不重发，applied 直接复用。
- 两个新进程竞争同 key，仅一条外部写入；之后修改输入冲突，再用原输入复用，写入数量不变。
- 命名空间重开稳定、不同存储不同身份、元数据与用户 key 分离、重复 create 与错误 revision 拒绝。
- 持久重用仍需明确授权，dry-run 不读写日志；占位/回执提交抛错或错误确认不伪造成功，已经真正提交的回执可供下一次安全重读。
- 等待占位时取消阻止 apply，已安装方法不受原对象后续替换影响；篡改请求、指纹、业务身份、回执或 revision 不调用服务。

首批 13 项通过；新增测试类型检查发现未先缩窄结果联合类型就读取 outcome，修正测试后 17 项和全量 315 项均通过，没有以类型断言屏蔽失败分支。上述是作者验证，不代表独立审阅、硬件断电或 Node 24 CI。

构建、测试类型检查、包边界、679 个本地文档路径链接及 diff 检查通过；链接检查不验证远端页面或锚点。
