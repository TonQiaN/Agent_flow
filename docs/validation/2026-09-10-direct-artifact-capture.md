# 直接物化归档与恢复验证

本轮处理 Issue #13 的 Catalog checkpoint/restore 中间目录。先查 Blackbox artifacts.py 的树物化、目标父目录暂存和验证复制，以及对应文件历史（v0.1.22 / 5610d1b，树支持提交 93200c8），再核对当前恢复工作目录的保留边界。保留本项目独立可写输入，不照搬只读挂载策略。

## 实现

ArtifactStore 和 ArtifactArchive 都增加可选 captureMaterialized，接受受信宿主安装的 ArtifactMaterializer。方法在首次异步等待前固定，不进入请求或持久记录。目标存储分配一个私有暂存范围，物化器在其 data 目录生成独立副本；存储复用同一份文件检查器原位读取、校验、同步，避免再复制文件。校验继续包含链接/硬链接、大小与数量、SHA-256、媒体、JSON/contract 和读取稳定性，并检查物化文件与目录的所有者和私有权限。

临时快照的私有登记保留数据根和完整清理范围，release 清理其中所有本次暂存。归档把验证后的原文件树移动到发布范围，仍按原文件/目录/清单同步、原子发布和归档根同步顺序返回引用。物化失败只删除本次范围，归档不增加删除能力。

Catalog 保存时把实际源快照的 materialize 安装给归档；加载通过原严格验证后，把实际归档的 materialize 安装给临时存储。目标支持新端口时无需 Catalog 中间目录，且沿用清单内容比较、物理存储 ID 与逻辑收据分离。目标不支持时保留原路径回退。同一存储根内的重叠物化仍拒绝。

## 验证过程与结果

本地 Node 26、真实 Docker、合成 Agent 协议；没有真实凭据、官方模型或学生材料。

- 定向存储/Catalog 34 项通过，约 2.01 秒。
- 最终常规测试 305 项通过，约 8.17 秒，0 失败、取消、跳过。
- 最终 Docker Agent/检查点/恢复 42 项通过，约 100.93 秒，0 失败、取消、跳过。包含阶段中断、接纳 A 保留、连续 B 中断、Strict 收据拒绝、真实脚本归档失败、并发恢复、CAS 拒绝迟到写入及联网资源恢复。

新增 6 项测试覆盖直接往返、原位验证、独立释放、两类接收存储的部分写入/符号链接/硬链接/权限/契约失败、源快照及归档损坏、归档发布前/后的两个真实 SIGKILL 边界，以及 Catalog 新端口/旧归档回退。原位验证通过发布前后同一文件 inode 证明没有第二份数据复制；这不复用原始宿主输入 inode。释放临时快照后归档仍能重新物化，无关相邻文件及原输入保持原内容。

首次定向 33 通过、1 失败，是 macOS 临时路径别名与 realpath 的测试比较不一致，修正断言后通过。首次常规测试的代理用例遇到沙箱拒绝 loopback listen；在允许本地测试 socket 的环境重跑后全部通过。首次 Docker 回归 36 通过、6 失败，新增加载断言错误要求工作目录不存在，而脚本运行可能已创建该目录；修正为加载前后目录存在性与条目一致，不改变产品实现。失败注入同步挂到实际使用的 captureMaterialized 入口，继续验证归档失败阻止接纳及后继执行。

构建、测试类型检查、包边界、673 个本地文档路径链接及 diff 检查通过；链接检查不验证远端页面和锚点。上述为作者检查，不代表独立审阅、Node 24 CI 或硬件断电验证。
