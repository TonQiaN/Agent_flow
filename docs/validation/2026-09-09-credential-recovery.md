# 凭据备份恢复验证

## 范围与预检

基线 a171e61，Refs #11，复用认证生命周期决定，主负责开发者仍为项目负责人，Codex 实施及作者自查；无独立评审或远端 CI 结论。全部使用合成凭据，不读取真实账号、调用 OAuth 或模型服务。

先核对 Blackbox Agent Flow v0.1.22 / 5610d1b 的 credential_recovery.py、test_credential_recovery.py 及 f508c78 修复。参考只保留可识别的健康快照、健康 live 不回滚、无安全快照不恢复的原则。Blackbox 直接容忍缺失 live 并从 .last-good 复制，其退出删除未同步清除该快照；当前不沿用该行为。当前宿主记录使用原子替换，Harness 只修改临时副本，恢复条件因此明确为宿主已提交封装的尾部截断，而不是任意 native JSON 损坏。

## 实施与检查

存储加入独立 recover 管理接口及 CLI auth recover；Engine 只声明非秘密结果接口，不增加 provider 恢复分支。备份与 live 使用同一受检记录及私有权限，替换/删除前持久清除旧备份，恢复同一 generation/revision。健康、缺失、不可用、恢复成功分开报告；恢复保留现有锁语义。

专项覆盖实际尾部截断、版本不增加、健康新记录不回滚、陈旧 revision/generation 拒绝、删除清备份及残留备份不复活、未知内容/schema/编码、过早截断、无备份、损坏备份、身份/权限/链接、执行与管理占用排他、同内容配置/刷新建立旧记录备份，以及编译 CLI 的非秘密状态与拒绝结果。

五个真实 fork/SIGKILL 故障点覆盖：替换 live 前、替换 live 后、删除 live 前、删除 live 后、恢复 live 前。使用纯存储子进程，实际拦截对应文件操作后强杀，确认产品恢复先报 CREDENTIAL_BUSY。测试仅在确认这个独立纯文件写入子进程已退出后，清理自己的合成锁以检查磁盘结果；该步骤不是产品按 PID 解锁功能。新写入/删除崩溃后无旧备份可回滚，恢复中断则匹配备份保留。

## 发现与修复

- 原备份后缀会与合法引用 shared.backup 的 live 路径冲突，反例实际出现 CREDENTIAL_IDENTITY_MISMATCH；改为合法引用不能使用的隐藏前缀，两个引用的配置、读取和删除互不影响。
- 同内容旧记录回存初版仅写规范备份，旧 live 字段顺序与其不一致，前缀恢复条件无法成立。新增旧字段顺序用例复现，改为必要时持锁规范化 live，generation/revision 不变。没有放宽完整身份和版本核对。

- 通用文本读取器会去除 UTF-8 BOM，带 BOM 的截断前缀原先被误判为可恢复；实际复现后，宿主存储记录读取保留 BOM 再核对原格式与前缀。Blackbox 的 utf-8/JSON 识别也不会把 BOM 当作正常 JSON 前缀；普通凭据来源读取行为未改变。

首轮 23 项专项通过；旧记录修正后的完整回归 278 项通过。随后补齐 BOM 反例并修复，最终 `npm run check`（Docker、egress、三个固定 Harness 镜像均启用）278 项通过，0 失败、0 跳过，约 107 秒；包含构建、测试类型与依赖边界检查。136 个本地文档链接及 git diff --check 通过。

## 限制

只恢复保留完整身份/版本前缀的尾部截断；不恢复缺失文件或任意损坏，不验证远端凭据有效性。测试覆盖进程崩溃，不宣称模拟硬件断电、恶意宿主同时改写或跨机器协调。真实 OAuth、真实刷新、剩余组合矩阵及最终真实学生批卷仍未验收；不能因备份实现完成关闭整个 Issue 或版本。
