# DeepSeek 文件隔离偶发超时的诊断证据

2026-09-09，代码基线 9c2ef01，主负责开发者 @xiaoxuanli-a，Codex 作者排查。承接[矩阵核对](2026-09-09-matrix-readiness.md)记录的一次 90 秒 Runner 超时。本切片增强测试诊断，没有宣称修复文件服务或改变停止策略。

## 先查已有解法

先检查 Blackbox 本地 v0.1.22 / 5610d1b 的 runners.py、agent_container.py、Docker 集成测试与对应修复历史。已有做法包括 Docker 命令关闭 stdin、超时后按指定容器清理；其已知无网等待场景有独立判据。没有找到与本次原生文件服务子进程挂起直接对应的既有修复。当前文件服务已 end stdin，不能套用无网等待可接受的判据。

补充阅读 [Bubblewrap 上游实现](https://github.com/containers/bubblewrap/blob/main/bubblewrap.c)的父进程死亡处理和子进程监控。上游说明不能代替本机固定镜像的时序证据；本次没有据此归因于父进程死亡窗口、机器负载或服务端等待，也未更换镜像或加入推测性进程组清理。

## 已改变的可观察性

`deepseek-fs-seam.mjs` 在测试进程中记录单调序号、时间、文件操作名称、完成/错误、spawn/kill/exit/close 及 PID；不记录文件内容、请求参数或凭据。跟踪保留原调用结果、kill 返回值和原错误，测试退出前恢复 spawn 绑定；日志仍通过 Runner 原有有界 stderr 捕获。

两项原生文件隔离测试现在先保存私有 runner-result.json，只有全部业务和清理断言通过才删除测试目录。运行失败、断言失败或停止不明均保留已有证据，并输出本地证据目录。原本“容器已删除便删测试文件”的逻辑会丢掉失败日志，现在容器删除与证据删除分别判断。保留日志不表示容器仍在运行；停止与移除结果仍以 Runner 事实为准。

## 验证与限制

- 原生文件工具与 seam 两项检查通过；原 90 秒 Runner 时限未放宽。
- 同一 seam 在固定镜像、最多三个并发、总计 12 次的有界重复检查中全部通过，每次约 2.5–3.3 秒。没有重现原挂起，不能据此证明不存在竞态。
- 单独测试进程用临时加载器，将该合成 fixture 替换成明确 stderr 标记和退出码 27。测试按预期失败；之后直接核对 runner-result.json、完整 stderr 及标记仍存在，Runner 显示已确认停止且容器已移除。该预期失败只验证证据保留，不能计作业务通过，也不进入普通产品运行。
- 完整回归启用 Docker、受控网络及三种固定真实 CLI 镜像，281 项通过、0 失败、0 跳过，106.5 秒，包含构建/边界/测试类型检查；最后补充的失败路径目录提示另由上述退出码 27 探针验证。类型及 diff 检查通过。原失败和重复检查分别记录。
