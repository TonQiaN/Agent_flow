## 预检与实现范围

按已确认的 Issue 范围实现 NodeTask 调度；先核对 Blackbox v0.1.22 / 5610d1b 的 scheduler.py、storage.py、credential_leases.py、test_scheduler.py、test_credential_capacity.py 及既有调度/认证修复历史。参考事务领取、失联不立即回收和管理互斥经验；新实现不照搬整 Run Worker 或进程内容量。

## 已验证结果

环境：macOS、本机 Node v26.0.0、TypeScript 5.9.3、Docker CLI 29.4.3。临时 SQLite、子进程、Docker Alpine 脚本及合成数据；不使用真实凭据、官方模型或 Tutor 生产服务。

| 验收面 | 实际证据 | 结果与边界 |
| --- | --- | --- |
| 一次只执行一个节点 | 同一两节点流程执行两次 `runOnce`，第一轮只接纳 A、B 新入队；第二轮结束 Run；严格加载两种状态 | 通过，业务路由仍由正常引擎负责 |
| 重开与重复入队 | 新进程读同一队列/Run，重复 Run ID 创建冲突，取消后不能被领取 | 通过，无重复任务实例 |
| 共享角色和认证容量 | 真实两个子进程同时执行不同 Run；相同身份限 1、角色限 2 时 A/C 执行，B 等待；另一个实验把角色限为 1 | 通过，角色和认证容量分别限制，等待没有 Attempt |
| 启动失败与释放 | 工厂在创建 Attempt 前抛错，任务 blocked、owner 释放，其他任务可领取 | 通过，不自动业务重试 |
| 原子性 | 第二个记录条件冲突时第一个记录无部分写入；只读守卫不增加版本 | 通过 |
| 过期占用和迟到写入 | 旧进程在归属检查后、实际数据库提交前通过 IPC 暂停；期限后新 Worker 接管并完成 A，再恢复旧进程 | 旧提交 `RUN_REVISION_CONFLICT`，已采用 Run 和唯一后继保持不变 |
| 重复提交 | 已完成领取再次通过绑定 Store 写入 | `QUEUE_CLAIM_LOST`，不重复推进 |
| 未确认后继 | A 成功后构造 B 的未确认终态，核对队列不会借用 A 的成功释放 B | 通过，保留占用 |
| 正常停止与取消 | 活跃节点期间 drain/cancel；取消与领取同时竞争 | 通过，不继续领取，不复活已取消任务 |
| 实际 Worker 失联 | A 完成，B 实际容器运行后 SIGKILL Worker，删除原始输入，新进程恢复 | 旧容器清理后 B 新 Attempt，A 不重跑，结果为 seedAB |
| 查询故障恢复 | B 失联后注入不可达 Docker endpoint | blocked 并保留容量，旧容器仍运行，不启动副本；修复后显式恢复并清理旧容器 |

专项普通测试位于 `src/packages/integrations/queue/node-queue.test.ts`，12 项通过，其中包含真实进程实验。队列 Docker 测试位于 `src/tests/e2e/queue-worker.test.ts`，2 项通过。

## 失败与修正

- 首次队列 Docker 夹具因对象缺少右花括号而无法启动，两个测试均未进入业务验证；修正夹具语法，`node --check` 和真实 Docker 用例通过。没有修改验收断言掩盖失败。
- 初版过期占用测试没有记录实际 Attempt，启动前失败因此正确释放占用，与该测试的“执行未知”前提不符；补入活动 Attempt 后，过期和未知资源占用断言通过。
- 核对终态投影时修正了“前一个成功节点可能被用来释放当前未知节点”的问题，并新增回归。
