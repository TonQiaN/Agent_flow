# Issue 模板填写与边界演练

日期：2026-09-08。关联 [Issue #6](https://github.com/TonQiaN/Agent_flow/issues/6)；方法：将有代表性的工作逐字段填写到实际五类 YAML 对应的小节，核对是否遗漏信息或把研究/计划误写成完成。Codex 编写与内容自查，未另行多人审阅。

本文件是填写验证记录，不是第二套可维护模板。后续改动只调整受影响样例；正式字段以 `.github/ISSUE_TEMPLATE/` 为使用入口，理由见七份决定。**以下 12 例均未创建真实 Issue；产品、故障、研究结题和依赖升级是模拟材料，不能当作实际执行证据。** Issue #6 例借用真实范围，完成事实另查 [实施验证](2026-09-08-issue-templates.md)。

## 覆盖与核对结果

| 例子 | 类别 | 核对重点 |
| --- | --- | --- |
| 外围时间回放、节点能力配置、父项总览 | 功能 | 正常/边界行为、分层、跨模块与父子结构 |

演练能在五类字段中表达这些工作，无需额外主类型或强制产品测试。每例保留待验证清单；结构核对、实际表单展示的执行范围与结果见实施验证记录。

两种决策验收反例也已进行内容对照：候选方案依赖的关键环境证据缺失时，记录补证责任与阻塞，不能把推荐当最终结论；若本项另外承诺模板或代码，决定写完后验收仍未完成，必须交付并验证其余产物。仅决策例的正式正文也须自足，不能只有一个外部资料链接。
