# 凭据环境注入与 DeepSeek 无密钥文件执行

2026-09-09，Refs #10/#11/#12；主负责开发者 @xiaoxuanli-a，Codex 作者自查。基线 927f966，后续本切片改动；无独立审阅或远端发布。原 Issue 已明确环境认证组合不额外挂载密钥文件，本次修正实现来满足原要求，不扩大凭据访问授权。

## 依据与实现

按用户要求先核对 Blackbox v0.1.22 / 5610d1b 工作树中的 `runners.py`、`api_keys.py`：命令只追加 `--env` 和变量名，值经 Docker 客户端环境传入。旧项目仅作参考，不成为运行依赖。

新增独立 `EnvironmentExecutionCredentialBinding`：短租约内读取已选源，转换为严格受限的凭据变量并记入脱敏器，然后释放源锁；执行期间只保留内存快照。不创建工作区密钥文件，不回写源存储，管理轮换或删除不被旧执行覆盖。身份、资源、停止与清理仍由同一执行结果核对；状态未知保留 release 门槛。

`PrivateStateBinding` 增加可选的秘密环境方法，值只进入 Docker create 的客户端环境。普通 `Invocation.env` 仍不接受密钥，路径环境仍只接受受限 state 路径，DockerOptions 不新增秘密字段。凭据变量名限定为受限的 API_KEY/TOKEN 名称，不允许 PATH、NODE_OPTIONS、代理或 AGENTFLOW 配置覆盖；与路径环境同名时拒绝。值不进入 argv，进程失败只返回静态错误。

DeepSeek Adapter 的认证声明改为变量名，宿主配方选择环境绑定。固定启动器只读取 DEEPSEEK_API_KEY，经有界格式检查转交 CLI，不查找遗留文件或其他来源。订阅组合继续使用原文件绑定和条件刷新；本阶段保留的旧不可变文件快照 API 已不用于 DeepSeek 组合；后续 PR 审查确认无当前生产调用后移除了该入口及对应配方分支，见[认证决定](../../.agents/decisions/product/README.md#p-20260909-auth-lifecycle)。

Docker daemon 管理员可以查看容器环境，属于可信宿主边界；本实现不声称对其隐藏秘密。工具进程仍通过独立 PID 视图、文件隔离与清空继承环境保护父 CLI 的密钥。普通结果不抓取 Docker Config.Env；原始日志仍保持私有。

## 实际验证

环境为 macOS arm64、Node 26、Docker；DeepSeek 原生镜像 dsh 0.1.1-rc.2 / Node 22.23.2，镜像 ID `sha256:a92f35565532db0e3c9ace1454754a0232a35ff413d31ebe3c7a90e7ae78916b`。所有密钥与业务材料均为合成数据。

- 新增三组绑定测试：并发快照、轮换/删除后无回存、没有任务文件、公共序列化与脱敏、调用方身份修改、错执行与未知停止拒绝、取消后确认清理、异常释放、非法变量和值、源/转换错误不泄露。
- 新增真实子进程运输测试，以临时 Docker 客户端替身观察参数与环境：选定值覆盖终端残留值，argv 只有变量名，宿主环境不被改写；错误不回显值，非 create 命令和配置型环境注入拒绝。
- 更新完整组合测试：真实 Runner、受控代理、宿主环境绑定、生产启动器、会话采集、Adapter 和 AgentExecutor 配合协议 CLI 替身；容器内确认没有密钥交接文件，正常/多出口/错误产物/缺失记录/非零/取消/版本漂移路径保持正确。此用例不是官方 CLI 联网证据。
- 原生 dsh 使用本地合成 HTTP 服务：宿主环境绑定进入真实启动器，22 次工具调用与 23 个模型步骤成功完成，文件/Bash/grep/glob 隔离、父进程环境保护、图像请求及结构化出口维持通过。额外验证无 key/非法 key 时不使用遗留合法文件，失败模型、取消以及采集竞争不能产生成功证据。
- DeepSeek 相关 10 项集成检查全部通过；完整 `npm run check` 启用 Docker、egress 及三个已选镜像后 **213 项通过、0 失败、0 跳过，约 104 秒**。包括 Codex/Claude 文件认证及 Workflow 回归。

单元测试的显式读取秘密只发生在受信测试侧，用于验证传输；没有在用户可见输出或仓库中保存真实秘密。没有读取真实账号、调用官方模型或写业务系统。
