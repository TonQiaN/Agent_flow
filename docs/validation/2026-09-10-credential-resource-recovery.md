# 不可变凭据执行资源恢复验证

## 范围与依据

Issue #13，基线 88f51d8，主负责开发者 @xiaoxuanli-a。按已有授权实现不可变 API key 执行资源的共同恢复，沿用[持久化决定](../../.agents/agent_notes/product/README.md#p-20260909-run-persistence)。此处是独立资源端口，完整 Agent Workflow 仍未验收。

先查 Blackbox v0.1.22 / 5610d1b 的 runners.py 订阅租约与 API key 无执行占用分支、api_keys.py 的按变量名注入、credential_leases.py 与 test_credential_capacity.py，并核对 f508c78 的订阅刷新收尾。当前 FileCredentialStore 的目录占用在宿主死后会保留，不能直接套用旧 flock 自动释放；本轮不清除遗留占用、不改写订阅刷新规则。实际源存储短租约已结束后，API key 执行不再需要源写入权，可以独立清理容器。

## 实现

PrivateStateBinding 提供可选成对资源定义与管理恢复能力。不可变环境绑定给出 credentialRef/service/method、环境变量名称；不含 key、内容摘要、generation/revision。管理绑定只关联一个已验证资源，拒绝 prepare 和秘密环境读取，不能配置或读取存储。共同 DockerBackend 在核对私有目录标记后关联绑定，使用 Docker v3 描述；停止、代理/网络逐项移除和目录释放规则不变。缺少该能力的文件/订阅绑定和交互仍拒绝。

CredentialHarnessRunner 的第三参数变为 CredentialRunPersistence，分别含 version 与可选 execution 端口。版本日志及完成回调先结束，获取并复制凭据、释放源短租约之后，再由共同 Runner 保存模型执行资源和启动记录。新 executionResourceDefinition / restoreExecutionResource 目前只支持 environment 配方，三个提供方共享组合逻辑；订阅明确拒绝，恢复调用不访问存储。

DeepSeek 配方声明实际变量名称，并在真实绑定产生的 Docker 定义中逐项核对；真实环境与预先固定描述不同，在分配资源前拒绝。Agent 描述纳入完整 Docker v3、固定镜像及代理代码摘要；后续实际执行重新准备并比较，不把仅有非秘密选项当作完整定义。原普通未冻结组合保留原行为；已冻结组合继续使用固定镜像，新镜像标签验证使用新组合。

## 故障与反例

新增 12 项实际 Docker/SQLite/新进程测试：在 allocated、create_completed、start_completed、完成后暂停并 SIGKILL；工作目录丢失；源 key 已轮换/删除；身份、变量名称及代理摘要变化；查询故障后重试；资源保存拒绝；获取凭据期间宿主死亡仍保留 CREDENTIAL_BUSY；订阅资源定义拒绝且不访问存储，以及普通 run 同步保留启动状态、禁止稍后首次定义与之竞争。资源回调内重新取得并释放真实测试存储租约，证明原短租约已结束。恢复进程中存储的所有方法均为拒绝调用的替身，调用数为零；核对任务/代理/两张网络全部缺失，原输入与当前凭据记录不变。材料、镜像和密钥全部为本地合成，未请求官方模型。

新增 2 项普通测试核对管理绑定不执行、不读 key、不可重复关联或跨资源释放，描述不会随调用者修改变化，拒绝进程配置变量。DeepSeek 合成组合增加探针→探针完成→执行资源的顺序、定义一致、源租约已释放及无密钥记录断言，继续验收正常接纳、失败、取消与产物交接。三种 Agent 定义与既有版本探针用新命名阶段参数回归。

自查发现新增缓存等待会使普通 run 在标记 started 前先让出执行权；先核对 Blackbox execution_plans.py 的已解析计划与预检固定边界，再恢复普通路径首个 await 前的启动标记，并增加立即并发调用定义的反例。
