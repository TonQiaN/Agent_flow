## Issue 级覆盖与剩余验收

#9 的定义校验、身份、输入副本、文件边界、outcome、用户路由/返修、进程内控制及模拟 Effect；#10 的独立 Adapter、参数、原始证据和终态；#11 的来源、存储/绑定、登录/刷新协议、有限恢复、容量和清理；#12 的独立 Runner、Docker 资源、捕获、超时取消、输入/输出及网络限制，分别继承基础审计逐条链接及上述后续记录。没有用测试总数替代条目核对。

当前没有在这些已明确范围内识别出另一项必须先实现的认证管理入口。以下要求仍开放，矩阵及 #9–#12 不能关闭：

- Codex 官方模型已通过此前三次合成批卷/返修调用；本切片没有重新调用模型。Claude、DeepSeek 尚无官方凭据经产品 Runner、真实原生 CLI、同一业务 contract 完整接纳的证据。

- 真实矩阵中图片输入、多出口和所选配置的联合证据须按 #10/#11 的组合范围逐项记录。当前共用批卷入口为 JSON、单一 Agent 出口；Gate 的 revise 是确定性路由，不能冒充模型多出口验收。

- PR 相对 base 的决定/实现/测试核对、实际审阅与合入；本地检查通过没有提供这些证据。三个现有 PR 的发布安排仍为独立待办。

新增入口的初版引用正则与领域规则不一致：会拒绝合法冒号引用，并可能放过末尾换行。已用反例复现，改用领域 isIdentifier；不新增一套凭据身份规则。

第一次完整检查 280 项通过；补充引用反例后的检查出现一次 DeepSeek 文件系统 seam 在 90 秒达到 Runner 超时（其余 280 项通过）。先查 Blackbox Docker 测试：其 stdin EOF 和无网等待说明不直接解释本次独立文件服务；本项目已经关闭 stdin，不能借用旧测试“等待无网可通过”的判据。随后同一镜像单独两项隔离测试通过（10.6 秒），最终同一代码完整 281 项通过（106.5 秒）。没有放宽时限、跳过测试或改写失败结果。

该单次超时的根因尚未定位：这不是已证明的产品修复，也不能无证据归为机器负载。保留稳定性排查项，后续应在不复写产品判据的情况下捕获失败时的具体文件操作、子进程和 Runner 原始证据。共用入口的完成与这一已有隔离服务的可靠性调查分别记录。
