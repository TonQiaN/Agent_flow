# JSON 文件转换与来源恢复验证

本轮承接 a412b44，主负责开发者 @xiaoxuanli-a，Codex 作者自查。先核对 Blackbox 的宿主执行收据链、输入/输出摘要绑定、下游物化及收据重新绑定拒绝测试。选用其“保存已接纳事实并沿前序验证”的原则，未移植旧运行模型或改变当前可写隔离输入约定。

## 实现

FileJsonWorkflowCatalog 新增 registerJsonFile：登记时固定相对 JSON 路径、outcome、读取上限；内置读取只消费已验证的独立文件快照，不接受任意回调或保存代码。读取核对大小、摘要、稳定性和 UTF-8，随后验证输出 contract。旧 register 回调仍支持普通调用但不能持久启动。

引擎新增可选 checkpointAcceptance；实际已校验结果的来源证明与 JSON v2 封套一起原子接纳。编译捕获实际端口，预检要求 restoreValue。加载按当前能力拒绝缺失、降级或结构不正确的证明，再通过一次性请求恢复。文件/JSON 所有者使用冻结的 contract 信息分派，不公开任意收据导入。恢复协调允许明确提供 checkRecovery 且没有资源端口的文件到 JSON 读取；普通回调由其实际绑定检查拒绝。

## 实际验证

新增 3 项 Catalog 普通测试覆盖登记参数复制、路径/上限/缺失文件、读取摘要变化、结果与来源证明一致性、伪造请求和普通回调拒绝。原 5 项文件转换测试继续通过。

新增 8 项真实 Node 子进程、SQLite 和文件归档集成测试：读取前/读取后 SIGKILL 后删除原始目录及临时副本，恢复同一 NodeTask 的 Attempt 2；已经接纳转换后在下游中断，恢复只调用下游，原收据和输出保持；path/limit 变化及普通回调在写库/调用前拒绝；v1 降级与身份、前序、摘要、outcome、输出篡改拒绝；旧活进程迟到结果不能覆盖恢复后的 Run；两个恢复者在读取同一 revision 后竞争，只有一个实际转换；后续加载验证失败时撤销已恢复转换收据。

定向 27 项通过，0 失败/取消/跳过，约 4.14 秒，包含原严格加载器回归。最终完整普通回归 351 项通过，0 失败/取消/跳过，约 13.21 秒；受影响真实 Docker 回归 51 项通过，0 失败/取消/跳过，约 143.70 秒，涵盖 Agent、通用阶段、检查点、恢复协调及 Tutor 文件脚本。构建、测试类型和依赖边界检查通过。

## 范围限制

使用合成 JSON，不读取私有学生材料、真实凭据或调用官方模型。Docker Agent 回归使用协议替身，不代表真实 Harness 矩阵验收。此切片未把完整 Tutor 应用切换为持久化，也未完成 publication.json 生产与发布审批组合、订阅来源恢复、整个 #13 或后续队列/重试/并行。未做独立审阅、远端 PR 发布、Node 24 CI 或硬件断电验证。
