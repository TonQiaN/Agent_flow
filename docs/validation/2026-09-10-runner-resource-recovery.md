# Runner 资源持久化与实际进程中断验证

2026-09-10（悉尼），主负责开发者 @xiaoxuanli-a，Codex 实现与作者自查，关联 [Issue #13](https://github.com/TonQiaN/Agent_flow/issues/13)。本次落实 Runner 资源端口，不声明 Workflow 新 Attempt 恢复已完成。

先检查 Blackbox v0.1.22 / 5610d1b 的 runtime.py `_reset_interrupted_units`、runners.py 确定性 container/sandbox 身份与清理失败处理，以及 tests/test_runners.py 的创建超时、清理失败用例。参考稳定执行身份和失败保留清理责任；本项目遵守已经确认的新 NodeTask/Attempt 语义，不复制旧 pending 重置或整 Run 锁。created 与正在提交的 start 之间的竞争沿用本项目既有 Runner 的实际状态复核，本次恢复进一步要求移除容器后才确认收尾。

## 实现

Runner.run 可接受资源保存端口，实际描述/分配后、准备和创建之前完成耐久写入。恢复核对实际环境和身份，再安装只用于核对与停止的 backend 关联。Docker 绑定完整身份、固定镜像、独立目录及宿主资源标记，拒绝恢复旧资源后重新创建/启动。工作目录缺失仍通过容器证据核对；存在目录的释放必须验证归属。存储不调用 Docker，Workflow 不直接调用 Docker 命令。

## 验证

首次针对性 22 项全部通过。随后完整 `npm run check` 的依赖边界、构建、测试类型、249 项普通测试及 99 项端到端测试全部通过：共 348 项，0 失败、0 跳过、0 取消，两组耗时合计约 584.0 秒。

完整回归期间的自查另发现配置根目录带末尾斜杠或 ./ 时，资源校验会拒绝 backend 自己生成的规范路径。先查看 Blackbox loader.py 的路径 resolve 处理，新增反例在修正前确定性失败。完整回归结束后，只规范化配置根目录进行比较，保存记录中的路径仍严格匹配、拒绝逃逸及冗余段。然后重新构建、检查依赖和测试类型，并执行最终 23 项针对性检查（7 项已有 Runner、5 项新增 Runner、1 项路径反例、10 项真实 Docker）；全部通过，约 20.6 秒，全部 Docker 恢复夹具使用带末尾斜杠的配置目录。348 项完整回归发生在这项最终路径修正之前，没有把它写成最终代码的再次全量运行。变更文档 133 个本地链接和 diff 空白检查通过。

普通测试覆盖真实调用顺序、持久写入失败不进入 prepare/create/start、缺少描述不分配、普通执行兼容、非法身份/环境先拒绝、停止确认但移除失败不能释放、重试与并发清理。

真实 Docker/SQLite 子进程场景覆盖：

- 分配资源并保存后、创建后、运行中、非零退出后分别 SIGKILL 宿主；新进程通过共同 Runner 恢复句柄查询预期状态、停止和移除，然后释放目录。宿主输入保持不变，恢复不写数据库。
- 工作目录删除后仍能核对和停止运行中的容器；测试先移除容器后，新进程能确认 absent 并清理残余目录。
- 保存端口在提交资源事实后抛错，实际 Docker 未创建或启动；新进程仍可检查已保存的资源身份。
- 环境、资源 ID、目录、内部身份、额外字段或宿主标记变化会拒绝；原容器继续运行，修复测试记录后正常恢复。
- 同名容器完整标签归属不匹配时，query 拒绝、stopAndRemove=false，测试容器未被停止。
- 仅在恢复子进程将 Docker 目标指向不存在的测试 socket，query 失败、停止不确认，宿主确认原容器仍在运行；后续正常连接的新进程完成收尾。
- 同一 backend 并发恢复同一记录只有一个成功；这不替代两个独立恢复者的持久 CAS 验收。

测试只通过明确捕获的测试资源 ID 做最终清理。没有真实凭据、官方模型调用或学生材料；本地 Node 26，未运行 Node 24 远端 CI，无新增独立审阅或发布。
