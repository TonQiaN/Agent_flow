# 0.1.1：最小工作流与真实 Agent 执行

## 目标

使用者可以定义 Component、契约和路由，通过受控 Docker 环境运行 Agent 并验证输出，完成精简批卷/复核/报告闭环。

## 范围与非目标

#9–#12：Workflow/Component、三个已选 Harness 组合、认证与 Docker Runner。先跑通首个真实组合，再补其余组合。不包含持久恢复、队列、自动重试、并行、前端或生产发布到 Tutor 数据库。

## 版本验收

逐项满足相关 Issue；运行 Tutor 合成批卷回归和选定真实样例，分别记录引擎契约、产物质量、已知限制。业务代码和真实答卷不进入引擎核心。模型输出不做逐字一致性保证，失败 Gate 不得绕过。

## 关联工作

预计五个功能 PR：执行基础 → Docker Runner → 首个 Harness/认证 → Workflow 闭环 → 补齐三个组合。每层有自己的决定、代码和测试，按真实依赖短栈推进；数量随可审阅范围调整。
