# 用户请求原文

来源：2026-09-07 当前 Codex 对话。仅作原始资料保存，不是另一份正式决策。

让我们一个个点讨论研究并开发，现在讨论决策生命周期。由于讨论的是生命周期，所以就决策的具体内容也会一并讨论和设计。

1. 决策的生命周期从在决策文件里写，变成抽出来变成文件夹树管理。
2. 生命周期的分类里不单独列出来被替代的这一层，改为在决策里直接写alternative方案，然后一一说明为什么不选用alternative方案。这参考了一份短笔记要至少保留的内容的建议。所以被替代的方案可以合并到对应的新方案中的方案考量中，记录否决理由等，不能和proposed，implemented，archieved，rejected等在一个层面。
3. 因为一个决策如果不记录相关类似观点的比较，选择原因，容易导致在开发中自动优化中让ai工具不断重复着思考和否决。
4. 同时专门加上被明确拒绝的方案，里面的决定方案是专门放进去避免重复研究的。
5. 非平凡改动必须要有对应的决策记录。
6. 决策的事实应当保持唯一，来增强决策记录系统的信息密度。决策管理系统的一大目标就是让提供给ai和人类看的文档的信息密度够高，够有组织性。因为所有的原始文件，原始资料都保存下来，噪声过大，不利于vibecoding开发和人的回头审计审批追溯。
7. 决定描述期望，使用指南描述现实。
8. 验证与事故复盘可以直接在docs里记录，因为如果经历了完整的cicd，issue pr开发流程，完整测试等等，还会出现大的事故，那么值得专门提出来进行复盘，并永久记录。
9. artifacts可以再创建一个专门存放原始资料的文件夹，然后收录进去，这个文件夹除了artifact，还可以有会议纪要，录音，文件等等。里面管理不严格规范格式，不严格规范文件夹树等。所以也不需要让项目内决策链接到对应的artifact，原始资料的文件夹里的内容可能随时变，比较混乱，也避免这里的混乱影响到项目内的严谨。这是专门特意设计的，让不同开发者习惯兼容的地方。但是进入项目开发流程，决策文档留痕时，不同开发者就必须都用一套规范的流程。
