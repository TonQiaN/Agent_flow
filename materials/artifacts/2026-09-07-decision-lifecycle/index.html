用目录管理决策生命周期

正式正文入口 ↗

创建于 2026-09-07。

结论与边界

在产品、开发流程两个分类下，分别用以下目录管理决策。生命周期只由路径表达，正文不另写状态；同一决策 ID 同时只有一份正式正文。

目录 含义与开发效力
proposed 尚待决定，不能据此改变既有要求
accepted 已有明确决定，尚未全部落实；约束目标，不证明功能存在
implemented 在所述范围内已落实并验证，后续相关改动继续遵循
archived 问题退出当前范围或提案撤回；保留记录，不约束当前工作，不等于明确拒绝
rejected 独立且被明确拒绝的方向；记录拒绝边界与重开条件，防止重复研究

archived 使用该英文拼写。superseded 不作为并列状态：被替代的是同一问题下的旧方案，合并进正文的 alternatives，保留选用与放弃原因。一般未选方案也只在该处维护；独立问题的明确拒绝才建 rejected 记录，不复制完整理由。

多人审查目标与启动期取舍

保留 accepted，既区分采纳与实施，也为决策在实施前经过审查留出明确位置。鼓励同一份决策由多名开发者审阅：个人再认真也可能在某些问题上判断失误，错误一旦进入长期决定，会持续影响后续开发；共同审阅结论与 alternatives，也有助于同步开发者对项目的理解和掌控程度。

多人审查会增加协调成本、减缓推进。目前项目、管理系统和产品内容都在启动阶段，因此暂时直接设计、直接做，不把等待多人审查作为实施前置条件。已有明确采纳依据时仍如实登记决定，范围落实并验证后可在同一次任务中进入 implemented，无需为了形式停留在 accepted。

accepted 不代表已经有多人审查，implemented 也不补造审查事实。确认摘要记录实际审阅情况；未进行多人审阅就明确保留这一事实。未来若要引入固定人数、责任人或必须先审后做的门槛，需在本决定中继续讨论，不能由 AI 自动升级为现行制度。

状态转换

事件 操作
新问题进入正式讨论 在 proposed 建立笔记，先查重复问题与已有否决理由
有明确采纳依据 移入 accepted，记录实际确认与审阅情况；启动期按上述取舍直接推进，不等待多人审查
所述范围全部落实并验证 移入 implemented；部分完成仍留 accepted，进度在 docs 或工作项说明
整个独立提案被明确拒绝 移入 rejected，留下拒绝结论、边界与重开条件
问题不再适用或提案撤回 移入 archived，并写明原因；不能用归档代替拒绝理由
当前方案改选且已确认 更新同一正文，旧方案合并进 alternatives；新方案待落实时移入 accepted，验证后再移入 implemented
rejected 或 archived 出现新依据并重开 同一文件移回 proposed，保留既有拒绝或退出背景；重开研究不等于许可采用

只是在讨论修订时，保留原文件当前目录和结论，在末尾写清待决修订。不能把仍有效的已实现决定整体搬入 proposed，造成现行要求消失，也不能另建同问题正文来竞争效力。

归档不用于日常换方案。错字修正不触发状态转换。移动文件同时更新分类索引，其他正式引用通过稳定 ID 定位。已提交版本可用 Git 追溯，但关键理由必须在当前正文自足，不能只靠翻历史找回。

AGENTS.md 的职责分层与唯一书写决策

正式正文入口 ↗

创建于 2026-09-07。

结论与边界

项目内每份 AGENTS.md 的书写、职责和变更理由都由唯一一项书写决策完整负责。一项决定可以管理一份或多份 AGENTS.md，同一份 AGENTS.md 不能由多项书写决策共同管理。文件声明自己的唯一书写决策，决定列明其管理的完整文件集合。

本决定管理下列两份文件，并解释当前全部职责分工；此表是对应关系的主记录，文件内的回链用于反向定位。

受管文件 作用范围 当前书写职责
根 AGENTS.md 整个项目 项目阶段、知识边界、按任务读取入口、非平凡改动先有决定、编辑任一 AGENTS.md 的唯一归属要求
决策 AGENTS.md .agents/decisions 及其子目录 决策查重与提炼、生命周期转换、索引维护、真实确认与审阅记录，以及决策系统自身的书写纪律

根目录 CLAUDE.md 仍是 AGENTS.md 的符号链接，同一正文沿用同一书写决策，不单独建立另一套理由。未来新增 AGENTS.md 时，先确定唯一归属；职责相关时扩展既有决定，确属独立范围时才建立新的书写决定。修改既有文件回到其原负责决定，不能因为多改一次就增加一个共同负责人。普通错字修正仍沿用既有决定，无需制造新的取舍记录。

AGENTS.md 与 README.md 的分工

AGENTS.md 保存需要代理执行的简短指令，包含作用范围、读取顺序和必要约束；README.md 说明目录内容并提供导航，不另行维护一套执行规则。为什么这样分工、为什么写这些规则，集中在本决定中。详细操作说明放在 docs，原始讨论不进入 AGENTS.md。

根入口保留所有任务都需要的约束，把生命周期、唯一正文与 alternatives 等决策编辑细则放入决策目录 AGENTS.md；README 保留分类、索引、模板与维护入口。这样既能使用指令文件的专门加载机制，也减少普通任务的上下文负担和重复规则。

AGENTS.md 中可以按需引用产品决定或开发流程决定以定位领域事实。被引用决定管理其自身问题，不因此共同管理这份 AGENTS.md 的书写。若领域事实变化需要修改 AGENTS.md，在本文件的唯一负责决定里记录如何调整指令，再同步正文。

指令加载与作用范围

核对的 Codex 行为是：启动时从项目根目录沿路径加载至当前工作目录，更靠近当前目录的项目指令出现在后面；不会为了根目录任务自动遍历所有子目录。因此根 AGENTS.md 显式要求，在创建或修改决策正文、模板、目录与索引前读取决策 AGENTS.md，不能只依赖目录名推测它已自动加载。README.md 在此项目中承担导航职责。

这里的目录内细化只作用于相应范围，不将子目录约定写成全项目覆盖。其他 Harness 的实际加载行为需要分别验证；本轮未修改其配置。技术依据：OpenAI 官方 AGENTS.md 说明，2026-09-07 核对。

一份自足的决定保存选择、比较与否决理由

结论与边界

非平凡改动必须有对应决策记录。已有决定完整覆盖时直接引用；出现新取舍时更新该问题正文，或为独立问题新建记录。“必须有记录”不等于“每次必须新建”。

非平凡包括影响可观察行为、目标用户、架构或接口契约、数据与安全边界、依赖策略、开发流程及文档治理的改动，不能按行数判定。错字、排版、机械同步且不改变上述取舍的工作可简化。Bug 修复若恢复已记录行为可引用原决定；若改变行为或引入新取舍，则需补充记录。

正文至少保存问题、结论与范围、实际比较过的相似方案及选择/否决理由、影响与验证、重开条件、确认、实际审阅情况与重要变更摘要。审查政策见 生命周期决定。区分事实、待验证假设和建议，不为填表编造比较。原始资料消失后，决定仍应可理解、可评审。

每个问题只有一个稳定 ID 和权威正文。唯一性指完整事实和取舍的归属；索引、短入口提示和从正文生成的阅读视图可以存在，但不能各自维护另一套结论。不同决定间引用，不复制；运行指南描述当前行为，不再复制决策论证。原始讨论副本不属于正式决定。

结论与边界

项目决策是第一公民。产品与开发流程的取舍分别放在 .agents/decisions/product 和 development；当前架构、用法、结构、验证结果及重大事故正式复盘放在 docs；原始资料统一收容在 materials，其中可以有 artifacts、会议纪要、录音及任意其他文件。

决定描述期望，使用指南描述现实。即使经过完整 CI/CD、Issue/PR 和测试仍发生重大事故，也要在 docs/postmortems 永久记录影响、根因、为何既有检查遗漏及修正；结论不能只留在研究材料里。验证记录在 docs/validation，未完成的检查不能写成通过。

正式知识遵循统一流程；原始资料区不要求统一文件格式、目录树、索引或反向链接，不进入普通开发的默认上下文。原始资料治理的完整否决理由仅在 明确拒绝项维护。
