# 维护主 Issue 说明当前问题与期望改进

创建于 2026-09-08。

## 结论与边界

本决定负责 `.github/ISSUE_TEMPLATE/maintenance.yml` 相对 [主 Issue 共通规范](../README.md#d-20260908-issue-template-common) 的差异。表单帮助制定者表达需求，执行方案由对应负责人负责；本决定的字段约束仅适用于主 Issue。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的变化

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写或保留问题提示 | `problem` · 当前情况与期望改进 | 说明工程、文档或协作中出现什么问题，希望得到什么可观察的改善。 |
| 去除旧方法要求 | `change_plan` | 移除预设的改动、兼容与验证计划块。需要保持的行为、兼容要求和已知影响归 scope，最终文件与使用结果归 deliverables / acceptance；不要求建项者提供迁移、回退或测试步骤。 |
| 沿用共同字段 | 除 problem 外八项共同字段 | 按共通决定表达领域、责任、要求与实际进展，不换名加入方法要求 |

完整表单共 9 个输入块。标题前缀、保留字段的 ID 和交付物选项继续沿用；历史 Issue 不批量回写。

### 完成条件

维护验收落实实际文件和约定结果。文档、模板与协作约定同样可能是非平凡改动；若已承诺可用模板和指南，正式决定不能替代这些交付。依赖升级、重构或迁移存在真实兼容约束时保留该要求，具体实施和验证由负责人负责。版本和 CHANGELOG 的维护沿用版本决定，本模板不新增发版审批。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 维护作为所有工作兜底 | 入口少 | 研究、选择与工程成果混杂 | 按主要交付目标归类 |
| 共同目标外加 change_plan | 旧版担心遗漏影响和兼容 | 容易先规定路径并重复范围、验收 | 取消独立计划块，保留真实约束 |
| 文档、升级、测试等各立专类 | 提示更专门 | 模板数量增长但共性多 | 继续采用五类 |
| 每项都填回退和产品测试 | 检查表整齐 | 小文档工作产生无意义内容或虚假记录 | 按实际影响验证，不要求建项者先写方法 |

## 影响与验证

同步当前表单、共通说明与差异索引；核对输入块数、问题职责、方法要求的移除和实际需求的去向。主 Issue 填写案例应能在不知道实现方法时表达完整需求；子项不提供示范正文。#6 旧版的演练和线上检查保留为历史，本轮结果及未覆盖范围见 [本轮验证](../../../../docs/validation/2026-09-10-main-issue-templates.md)。

## 重开条件

真实主 Issue 反复遗漏必要事实、成果质量或边界，或共同提示造成无法表达的需求时，带实例修订原决定。子项是否提炼模板依据共通决定中的实践条件，不因主表更新自动推广。
