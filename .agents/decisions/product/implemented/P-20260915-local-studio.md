# 本机工作流展示与启动服务

创建于 2026-09-15。

## 结论与边界

#39 首版部署于团队成员自己的电脑。采用 TypeScript 本机 HTTP 服务和 React 前端；服务仅绑定 loopback，技术设置来自本机配置，页面只读。上传与启动使用同源校验、大小和文件类型限制、一次性输入校验及幂等提交标识。服务不向浏览器发送凭据。每次运行独立数据目录和执行子进程，共享同一个展示入口；保存最新元数据、引擎检查点/观察记录、不可变文件、事件和终止原因。

应用层以已登记的 examples 入口启动真实工作流；通过固定子进程入口跨越应用与示例边界，不开放客户端选择程序或任意宿主路径。现有完整工作流分别登记环境要求和材料表。原有 CLI 入口也使用共同记录目录，页面可以发现。工作台分配的运行 ID 必须传入原有检查、Map 与 Fork 入口，使元数据、检查点和子运行关联使用同一身份；单独运行 CLI 时保留原来的默认 ID。批卷上传同时检查原文件扩展名与 JSON 内容，不因目标路径以 .json 结尾而接受其他格式。Tutor 外部依赖缺失时明确显示条件，不替换为虚构流程。

结构与绑定均从实际已编译定义提取，历史只读取已保存记录。内部 Run/Attempt/并行子任务关联原样保留，序号和宿主时间驱动回放，回放没有执行副作用。原始文件复制到本次目录并校验摘要，浏览器只按注册文件 ID 取文件，禁止任意路径读取；新上传未启动前仍留在同一个弹窗。

前端框架和画布采用 React、Vite、React Flow，依赖精确锁定。其拖动、缩放、节点/连线选择适合本次展示交互；执行图不可在页面编辑。页面交互与浏览器验收在本决定下述章节定义。

## 画布与查看交互

节点默认展示任务：工作说明、完整 Prompt 或脚本命令、输入输出要求。当前定义从已安装的示例与执行器提取配置，只描述、不启动节点；历史页严格读取当次保存的绑定，不用当前 Prompt 补写旧记录。容器配置按任务执行、版本检查等用途区分；宿主函数、合成执行、运行时生成的命令与数据缺失分别说明，不能把“页面没接入数据”写成“没有容器”。任务摘要是当前定义的辅助说明，历史缺少摘要时保留原始 Prompt、命令和契约作为依据。2026-09-17 用户调查后明确要求“补齐展示”，据此完善已有范围。

第三层实现固定左侧导航、工作流目录、历史列表和设置页面；运行详情共用同一张 React Flow 画布。节点可拖动、画布可缩放，位置只影响本机浏览偏好。连线详情包含源/目标、outcome、返工上限和数据契约；节点详情按真实执行身份选择次数，分别显示输入、输出、容器设置与日志。运行、文件和历史错误使用明确的中文状态。

回放使用记录序号和真实时间，按选定时刻读取父、子运行的已保存修订；暂停/播放/逐条跳转仅切换视图，不能调用运行入口。按修订号或时刻直接查询所需快照，避免每一帧反复解析整段历史；跨父、子运行按同一全局保存序号限定边界，并以记录时间辅助展示；同一毫秒之后保存的修订不能提前出现。回放中切换子运行继续使用相同序号和时刻。最终招聘结论只在业务交付关卡通过后按二元结果展示；节点契约通过和整个工作流通过分别标注。文件 HTML 只读文本预览；PDF 由本地 PDF.js worker 渲染到 canvas 并提供分页和可访问文字，图片走同源预览。旧修订缺少时间时，只显示该修订本身；不能跨运行对齐的子运行、文件和事件明确标为不可回放，避免混入之后产生的信息。没有执行身份的节点不显示其他节点日志。

上传弹窗一次收集岗位、候选人、归属和全部文件；技术配置只读，上传按钮和拖放共用校验。同一逻辑提交跨 multipart boundary 保持幂等。窄屏切为单栏并保留画布、详情和导航。端到端 CI 从真实服务提交合成招聘到报告、历史、回放；Astra 在实际浏览器完成点击、拖动、截图识别，修正问题后重走路径，报告和截图仅保存在本机 materials/issue39-user-report。

节点业务产物归档属于本次运行的必需记录。产物归档回调失败时，节点返回明确的记录失败，不继续到后续节点，也不重复调用同一回调。已捕获的输出在调用归档前登记清理归属，失败后仍可按原执行身份释放临时文件；不能因展示记录失败丢失资源所有权。可选的 Harness 日志接收端失败单独标为采集不完整，不改写已经确认的执行结果，边界沿用 Harness 适配决定。

## 2026-09-16 交互修订

用户实测否定首版目录和画布的可理解性：业务工作流与技术示例平铺，节点按数组摆放后过度缩小，空详情栏和教学文案挤占画布，完整运行入口难以发现。本轮按用户明确授权重设计；上一轮功能检查不能作为这些体验问题已通过的证据，修订完成前不宣称通过。

目录明确区分业务工作流与技术示例。每个条目仍对应真实、独立的 Workflow 定义，名称、稳定 ID、节点数量和步骤预览共同确定边界；同类批卷的不同流程分别命名，不能把节点当作业务流程，也不把不相关示例拼成一个流程。节点只出现在所属流程画布或节点详情中。

流程工作区以画布为主要区域，压缩导航与工具栏，删除常驻教学说明和空白详情占位。节点按 start 与实际路线排序，主路径有方向箭头和步骤序号，返工线单独区分；默认缩放保证名称可读，完整图可平移、缩放和重新布局。节点拖动只改变本机布局，选中后显示可关闭的详情面板。流程定义不冒充运行状态；某次运行按该次已保存记录显示完成、当前、等待、失败和未执行节点，并提供定位当前步骤。

每个工作流直接查询自己的运行记录，提供最近一次完整运行入口；开始运行后直接进入其画布。运行页保留工作流返回入口、运行名称、状态、节点进度、结果和时间回放，使目录、定义与某次运行形成连续路径。并行子任务从所选节点的某次 Attempt.parallel.children 进入，并能返回所属节点和原轮次；等待时复用尚未结束的 Attempt 身份，不猜测任务归属。它们不混为新的业务工作流。

视觉参考为用户要求的 [Dify 官方画布](https://dify.ai/_astro/workflow.Dl7EY_X1_rPiFq.webp)、[ComfyUI 界面说明](https://docs.comfy.org/interface/overview)及其节点截图。借鉴画布占比、节点层级、连接方向和就地运行控制，不引入其执行引擎或复制素材作为产品资源。验收新增从目录找到完整招聘运行、默认视口可读且不重叠、按实际执行定位当前节点、无空详情占位；保留原有结果/文件/回放和失败场景回归，并由 Astra 按用户路径检查截图。

CI 在通过时也保存目录和画布截图，便于审阅者核对视觉结果；截图产出不替代人工判断。新的本地体验报告保存于 materials/issue39-redesign-report。

### 同日补充：横向浏览与曲线

用户在 731px 宽的实际页面补充确认：所有连线使用曲线，主路径从左到右展开，拖拽浏览，不必一屏展示全部；连线文字解释流转逻辑。按此要求改为横向主路径，分支在旁侧展开，同排的返回曲线从上方回到真实目标；跨排分支利用节点间空隙连接，不能穿过成功结束节点造成错误走向。首次打开和恢复布局保持可读比例；全图缩放只在用户点击“适应画布”时发生。保留回到起点及定位运行当前步骤，避免长画布中迷失。

每条连线始终显示横向文字：招聘流程说明传递的内容或检查条件，其他流程使用实际 outcome 的通用说明。返工同时标出目的和上限，点击仍可核对原始 outcome 与契约。文字和曲线不改变执行规则；运行与回放继续使用保存的路由结果。旧浏览器布局使用独立版本，避免折行位置覆盖本次默认布局。此次补充由用户直接授权，验证结果在同一验收记录更新。

## 2026-09-17 时间、产物与整体查看习惯

用户要求逐步时间、回放时间戳、按节点分类文件，并确认结果展示应兼容招聘之外的流程。延续此前明确的习惯：以完整工作流和画布为入口，细节按需展开；优先呈现实际进度、输入、输出和文件，减少教学文案；同名文件保留节点、任务与尝试归属，点击可直接到对应节点。

时间由已保存的快照与执行事件投影，不改写历史记录。节点起止记录与容器执行起止分别标明来源，未记录的时间保持缺失；排队、重试、返工及并行身份分别保留。回放显示完整记录范围、选中时刻和已过去时间，缺失时间或时钟倒退时不伪造耗时。回放中的未结束尝试和文件以当时可见记录为准。

结果页采用通用输出与产物入口，招聘明细是按工作流及数据结构选择的专门展示，不能仅凭字段名把别的流程当成招聘。通用页支持结构化值、任意内容的 PDF、图片和代码等文件；没有专门视图仍能阅读原值与下载产物。文件以归档来源和执行身份归组，原始上传、节点各次输出、草稿与来源未记录分开；同一归档多次引用保留关联，不能靠文件名猜节点。代码和 HTML 仅作为文本查看，预览有大小上限，不执行产物。

本轮依据用户“总结使用习惯，整体 review 并迭代”的直接授权继续更新 #42；实际检查与不足记录在验证摘要和本地体验报告，用户复看与独立审阅不由作者自查代替。

## 合并前的读取边界

公开定义与历史共用只读配置投影，不向页面传递恢复私有状态、凭据来源或宿主工作目录。日志翻页使用每个运行独立的连续记录缓存，刷新继续读取尾部，异步旧请求不得写入新运行。回放切换到较早修订后，失效的执行次数选择回到当时最近一次。结束标记先于快照读取，避免先读到旧快照、随后读到新的完成标记而停止刷新。批卷文件在浏览器和服务端均验证原文件为有效 JSON，失败不创建运行。

修订的全局序号用于跨运行回放边界；事件有独立序号，旧记录同一毫秒内无法证明事件与修订的先后时不提前展示该事件，已保存在修订中的输入输出仍可查看。实时日志保持完整，不能为回放补造新历史字段。
