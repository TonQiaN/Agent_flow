# 单岗位、多简历的证据招聘工作流

创建于 2026-09-15。

## 结论与边界

一次提交一个岗位及最多 12 位候选人的简历和补充材料，文件归属在启动前确认。单文件 20 MiB、合计 128 MiB、最多 64 个文件，每份文档最多 60 页；接纳 PDF、DOCX、TXT、Markdown、PNG/JPEG。限制同时用于前后端，依据首版单机处理和现有单组最多 62 子任务的界限确定。12 人乘 4 维评审为 48 项，不需要嵌套工作流；扩容再设计分批持久化。

真实引擎负责材料解析、岗位要求提取、四维独立并行评审、证据复核、有界返工、最终二元裁决和交付校验。每位候选人依据同一版本岗位要求评审，输入隔离，引用必须对应其自身材料或该岗位原文。缺失内容为未证实，冲突不等同于造假；只按岗位相关事实分析。每个最终报告的推荐严格二选一：推荐通过/推荐不通过；不设总分、加权评分或排名，未知和冲突必须解释对最终推荐的影响。面试问题是补充，不能代替二元结论。

材料解析在固定断网容器内完成，文本/页码保留原文定位，扫描资料采用 OCR 并标明来源。模型执行通过现有独立 Harness/凭据适配器；JSON 并行任务通过受信文件适配进入已有 AgentExecutor，返回先经过 JSON 和引用检查。临时输出在释放前归档，技术失败不能生成候选人不通过结论。证据检查失败触发最多两轮返工，保留版本；候选人级修正只影响该人，共享岗位规则改变需重新检查所有相关候选人。

代表性验证使用 1 个岗位和 3 份合成简历，覆盖两种二元推荐和未证实/冲突。真实模型完成正常路径；明确标记的确定性测试情景通过实际引擎产生失败、返工、重试、排队、并行和取消，不能在前端伪造状态。故障注入仅在本机测试模式启用。

## 方案考量（alternatives）

暂无符合记录条件的替代方案。用户曾暂选多岗位后明确改为单岗位，未给出比较理由，不补造。

## 影响与验证

复用 engine 的 Workflow、Map/Fork、NodeWorker、retry 和路由上限；新增文件与 JSON Agent 的可持久交接、招聘任务、严格结果/证据校验和可下载报告。引用逐条核验岗位/候选人归属、原文片段和定位。最终汇总确认所有候选人无漏项、两种允许结论、无评分字段；页面与 JSON/可读报告使用同一已验证结果。

## 重开条件

增加多岗位、更多候选人、人工审批或共享部署时重新评估容量和状态模型。

## 确认与变更留痕

2026-09-15 用户确认单岗位、多简历、逐项结论与证据、不设总分，并要求二元绝对推荐；随后明确授权完整实现及 stacked PR。设计参考 onto-flow 已提交结构与证据规则，未采用其评分阈值。用户另外授权创建 DeepSeek 专用测试 key。实施安排由 Codex 在授权范围内决定，@TonQiaN 主责，尚未其他开发者独立审阅。

实现约束补充：Agent 通过 JSON-to-files 适配直接使用现有执行链，JSON Map 子任务复用现有队列；宿主收集原始文件/页码引用后再判定返工。每次招聘启动固定文档、Agent、代理镜像的不可变摘要，防止镜像标签重建改变中途定义。候选人 ID 与维度由调度器绑定到任务，模型不必重复提供；模型若主动返回身份，必须与该任务一致，不一致时拒绝而不能悄悄纠正。报告同时保存决定性岗位项、未知/冲突影响说明和二元推荐。
