# 单层 JSON Map/Fork 与持久汇合

创建于 2026-09-10。

## 结论与边界

首版提供 Map 与固定 Fork 的结构登记接口。Map 输入为 JSON 数组，每项携带唯一非空字符串 ID，按原索引汇合；Fork 分支预先命名，按分支 ID 字典序汇合。每项只执行一个已有 Component；输入、所有 outcome 输出与汇合包均为明确引用的 JSON contract。拒绝文件产物、Effect、嵌套展开和非 wait-all 策略。

结构节点由引擎登记与推进，不在业务 Component 内等待其他 Agent。每项以一个稳定的内部执行记录保存普通单节点 Workflow 检查点，身份由父 Run、父 NodeTask 和项目位置确定，并由父展开记录关联；它不是可独立扩展的子流程。内部记录使用同一 RunRecordStore、正常引擎、Worker、恢复和重试端口，不建立另一套业务状态库或线程池。

父展开及全部初始项记录、队列引用在同一条件事务中写入，防止只展开部分项目。父任务等待时释放 Worker 和角色容量，子项共享现有角色/认证限制，并额外受本组 maxConcurrency 限制。全部子项最终结束后，正常队列重新调度父节点做一次汇合；已接纳子项不重复执行。汇合仍由正常输出 contract、路由与 CAS 接纳，失败仅汇总诊断，不伪造正常 outcome。待核对的旧执行保持阻塞，取消不能凭空证明其已停止。 未领取子项的取消与串行任务共用停止判据：普通记录须无活动身份，恢复记录须有旧资源清理完成事实；历史 Attempt 身份保留不能单独阻止已清理项取消。与重新领取竞争时，在同一索引/子记录条件事务中重核归属，已被领取的项只提交协作取消意图。

纯展开/汇合逻辑留在 engine，具体记录键及原子提交留在现有持久队列。使用已安装的单节点执行定义校验子记录，不能从存储内容加载新代码。最大项目数受当前 64 个记录条件的原子接口约束，首版至多 62 项；空 Map 产生空 items 汇合包，Fork 至少两个分支。字段与容量上限是实施细节，未宣称为用户逐字段确认。

## 方案考量（alternatives）

| 方案 | 收益 | 代价或不适用理由 | 取舍 |
| --- | --- | --- | --- |
| 关联普通单节点持久记录，共用队列与引擎 | 复用验收、尝试预算、资源清理和容量，等待无需 Worker | 需要原子展开及父子引用校验 | 采用 |
| 在 Component 内 Promise.all 并阻塞 Worker | 代码短 | 占用汇合槽位，另建并发/恢复逻辑，偏离模块边界 | 不采用 |
| 首版支持动态子流程、嵌套并行和文件汇合 | 表达力强 | 明确超出已确认初版范围 | 不采用 |

## 影响与验证

验证预先拒绝全部非法输入、Map 乱序与稳定索引、Fork 字典序、独立输入、wait-all 与无后继、组/角色/认证容量、取消、原子展开、部分成功后的重开/中断/重试和幂等汇合。Agent 的逻辑 JSON 交付仍须由已有可信执行/产物适配接口提供，结构节点不解析模型日志，也不恢复旧 result.json 文件清单协议。

## 重开条件

需要超过当前原子提交上限、并行文件、Effect、嵌套或动态子流程、非 wait-all 策略、多机执行或历史迁移时重开，不借初版扩展范围。
