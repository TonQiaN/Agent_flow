# Harness Adapter 只生成调用并解释执行证据

创建于 2026-09-09。

## 结论与边界

按 #10 已确认设计，统一 HarnessTask、调用计划、事件和最终执行事实；每个 Harness 单独实现并显式注册。Adapter 不读取秘密、文件系统或启动进程，不决定 Workflow 路由和业务产物是否有效。用户 prompt 原样传递，固定目录与宿主执行配置不由任务内容改写。

首个组合选 Codex 订阅与 Docker，针对实际容器版本 0.153.4 验证；本机 CLI 及旧声明为 0.146.1，不把两者等同。模型由调用配置明确给出并校验名称格式，远端账号/模型可用性以实际调用为准。初始只接受明确映射的推理档位、禁用子 Agent 和禁用搜索配置；预算、任意 argv/env、未知字段及未支持功能启动前拒绝，不静默降级。后续真实证据允许扩展同一 Adapter，不新建全 Harness 分支的公共执行器。

Codex 调用采用 exec --json、严格配置、独立 CODEX_HOME、忽略用户配置/规则、固定 cwd 和非交互权限。身份、业务输入输出目录继承引擎；安全权限配置拒绝模型工具读取或移动认证文件，并允许修改 input/work/outputs。外层容器和内层文件约束必须联合实测，未验证时不声称秘密隔离已完成。

真实沙箱探测表明 CODEX_HOME 下含 codex-linux-sandbox 启动别名，禁止读取整个目录会阻止沙箱启动。因此只拒绝声明的 auth.json/profile.json，保留该 Attempt 的临时程序可执行；状态目录仍逐任务隔离。已用合成凭据验证直接读取、符号链接、硬链接、父目录移动和 /proc root 读取均不能取出认证内容；这不代替真实刷新与联网集成验收。

### 临时任务副本中的元数据权限

Codex 0.153.4 对可写目录内缺失或空的 .git/.agents/.codex 默认建立合成只读挂载；本机真实启动和离线探测均发生该挂载的 remount 失败。Blackbox 的 0.146.1 定义没有对应修复，其独立 provider-state 修复已在本项目落实，不能把不同版本视为同一环境。官方 0.153.4 权限实现提供显式子路径 write 覆盖默认元数据保护的行为。

本项目只在固定 /task/input、/task/work、/task/outputs 的临时副本中，将这三个元数据子目录显式声明为 write。这些目录与同目录其他用户内容一样属于一次任务，不挂载宿主项目配置、真实仓库 .git 或引擎收据；协议配置仍独立只读，真实认证仍在 state 并明确 deny。所有输出文件继续经过同一 contract，不按元数据名字豁免输出，也不将这些目录的内容用于建立引擎信任。此选择实际放开了这些临时目录内的元数据写入，不能声称保留了原先的元数据只读规则；宿主原件与可信执行配置的隔离不变。

权限映射由 Codex Adapter 用固定路径生成，不增加用户任意权限字段、不预建占位文件或修改输入快照，不更换全局沙箱策略。验证须覆盖空目录/已有内容、真实启动、三个路径的元数据写入，以及认证读取/链接/移动和协议写入仍失败。先用断网合成凭据验证，再跑已授权实际组合；一次不复现不证明上游竞争已修复，仅验证该映射避开了不适用于临时副本的默认只读挂载。

stdout JSONL 的 turn.completed 是 Harness 正常终态证据，turn.failed 是失败终态；失败终态不再误报为缺失终态，也不要求正常出口响应。thread.started 之后、turn.started 之前可出现 item.completed/error 形式的初始化警告；只记录类型且不公开其载荷，不将警告单独当作失败或成功依据。其他业务 item 仍须在 turn.started 之后，终态后的事件仍拒绝。还须 Runner 实际退出 0、停止确认及完整采集才可返回正常结束。合法 JSON、聊天“完成”、单个消息或非空目录都不能替代终态。缺失终态、畸形事件、未知编码、截断、冲突终态及 Harness 错误为执行失败。相同终态重复只接纳一次；usage 只取明确终态字段，不遍历嵌套同名字段、不累计重复快照，缺失为 unknown。

普通事件由传入的脱敏接口处理消息/工具文本；认证层提供秘密过滤，Adapter 不取得秘密存储权限。保留事件类型、item ID、来源及 Attempt 关联；未知事件记录类型与诊断，不把未知载荷整段复制进普通日志。raw 原件保持私有。首个 parser 使用结束后完整流解析，不宣称实时推送或完整原生轨迹。

单正常出口不要求模型写完成文件；结构化多出口通过 output-schema 约束最后响应的 outcome，实际输出仍放 outputs 并由独立 contract 验证。schema 通过只读配置注入，不能成为业务 artifacts 清单。本切片先实现独立接口、计划与 parser；真实 Runner/认证/网络、文件交付校验及可信前序证据须继续在 PR3/后续 Workflow 切片接通。

首个联合执行入口在 integrations 中组合纯 Adapter、Profile、凭据绑定与 DockerBackend；不将 Codex 特例写入 engine Runner。先解析不可变镜像 ID，再用离线 Runner 在相同镜像内检查实际 CLI 版本，成功并清理后才申请真实租约。业务执行结果分别保留 Runner、Harness 与凭据收尾事实；正常 Harness 结束仍不代表文件 contract 接纳。失败后保留可操作的执行句柄用于可信停止/清理，不能因抛出异常丢失占用资源。

## 方案考量（alternatives）

| 方案 | 收益 | 代价 | 取舍 |
| --- | --- | --- | --- |
| 三个独立 Adapter + 显式注册 | 差异局限于调用/解析，可用替身测试 | 需逐个维护支持矩阵 | 用户确认采用 |
| 通用命令/环境透传 | 配置灵活 | 无法前置检查承诺和认证边界 | 不采用 |
| 从聊天尾句推断完成 | 不需要机器协议 | 无法区分失败、截断与真正终态 | 不采用 |
| 保持临时副本的元数据默认只读 / 预建空目录 | 沿用宿主仓库保护习惯 | 空目录仍进入合成挂载，已有复现且预建不构成可靠修复 | 采用固定临时子路径显式 write，重新验证可信目录隔离 |
| 默认 usage=0 或递归累加 | 表格容易填满 | 将未知写成零或重复计数 | 明确 unknown 与唯一终态字段 |

## 影响与验证

对应 #10 及 #9/#11/#12 联合边界。先验证注册、参数拒绝、原样 prompt、身份关联、畸形/截断/未知事件、终态冲突与 usage；随后用选定真实版本验证调用、文件权限、认证/网络和正常交付。仅 parser/替身测试不能关闭 #10，也不能称整个首个真实组合已完成。

2026-09-09 的真实离线探测要求 filesystem 使用 TOML inline table 与 deny 枚举，已修正映射。严格配置通过后仍遇 bwrap namespace 初始化失败，须在执行集成层兑现内部沙箱需求；不通过关闭沙箱规避。当前接口/parser 与存储共 46 组检查通过（含 Docker），真实模型调用未完成，详见 docs 对应验证记录。

## 重开条件

实际版本更改事件/参数或必需采集方式时重新验证并更新本决定及矩阵；不默默接受未知版本或从日志猜测字段。支持搜索/子 Agent/预算必须提供实际证据。
