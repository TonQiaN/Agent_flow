# Component 定义、输入输出契约与一次执行分离

创建于 2026-09-09。

## 结论与边界

采用 #9 已确认的最小模型：Component 定义身份、kind、输入 contract、各 outcome 的输出 contract 及实现引用。kind 区分 agent/gate/transform/effect；业务角色和执行资源不编码进 kind。Workflow 决定路由，Component 不调用后续节点。

Run、NodeTask、Attempt 分别表示流程运行、一次业务节点实例和一次执行尝试。对同一 NodeTask 重试创建新 Attempt；返修再次进入节点产生新 NodeTask。首个实现仅提供身份类型和校验，不提前实现调度、恢复或计数分配。

确定性函数返回结构化 outcome/output；引擎校验已声明 outcome 对应的 contract。执行异常、无效输入输出与业务拒绝分开：合法 rejected outcome 可以被接纳，抛出异常或输出违约属于执行失败。失败诊断不回显输入、输出或抛出的任意异常文本。

首期 JSON 契约采用 JSON Schema Draft 2020-12，显式登记 contract ID。使用 AJV 严格校验和 format 校验，不转换类型、不填默认值、不删除额外字段，不进行网络 schema 获取；此切片只允许本 schema 内的片段引用。登记时先校验 schema，保存独立副本；调用时提供独立 JSON 输入副本，结果接纳也保存副本，避免函数修改调用方输入或事后改变已接纳结果。

函数实现注册与定义注册分离。契约注册、定义注册和函数执行均可在无文件系统、无 Harness 的环境独立测试。执行前需要所有引用已解析，不以替身支持宣称真实 Agent 或容器支持。

后续文件和 Agent 切片继续遵循 #9：可写输入工作副本不回写来源；outputs 自动发现候选产物；单正常出口 Agent 正常结束且契约通过后由引擎赋值；多出口用结构化 outcome。文件契约、可信前序执行证据、Runner 和完整 Workflow 不属于本次 JSON 函数切片，不能通过移除此决定到 implemented 冒充整项完成。

## 方案考量（alternatives）

| 方案 | 收益 | 代价 | 取舍 |
| --- | --- | --- | --- |
| 定义、实现注册、契约与执行协调分离 | 替换实现不改变业务定义，可独立测试 | 需明确引用和错误边界 | 采用 |
| Component 内直接指定下一节点 | 调用链直观 | 路由耦合业务实现、难以复用 | 按用户已确认设计排除 |
| 强制所有实现写完成文件 | 协议表面统一 | 确定性函数额外文件交互，Agent 完成声明不可靠 | 使用结构化结果/执行事实，后续产物独立校验 |
| 校验时自动修正 JSON | 部分宽松输入容易被接纳 | 掩盖违约并改变输入 | 不转换、不补默认值、不丢字段 |

## 影响与验证

本次只对应 #9 部分验收，PR 用 Refs。测试契约错误前置、拒绝/失败区分、outcome 对应契约、注册重复及引用缺失、输入与已接纳结果隔离、错误信息不泄露。可信函数不是安全沙箱；运行不可信 Agent 由后续 Runner 处理。函数不自动获得生产 Effect 权限；本切片执行入口拒绝 agent/effect kind。

## 重开条件

真实业务需要外部 schema 注册、文件契约、跨进程执行或可信证据时在相应切片补充本问题边界。实际能力无法兑现 #9 时由主责调整，不能静默放宽校验。
