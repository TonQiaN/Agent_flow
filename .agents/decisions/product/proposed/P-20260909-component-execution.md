# Component 定义、输入输出契约与一次执行分离

创建于 2026-09-09。

## 结论与边界

采用 #9 已确认的最小模型：Component 定义身份、kind、输入 contract、各 outcome 的输出 contract 及实现引用。kind 区分 agent/gate/transform/effect；业务角色和执行资源不编码进 kind。Workflow 决定路由，Component 不调用后续节点。

Run、NodeTask、Attempt 分别表示流程运行、一次业务节点实例和一次执行尝试。对同一 NodeTask 重试创建新 Attempt；返修再次进入节点产生新 NodeTask。首个实现仅提供身份类型和校验，不提前实现调度、恢复或计数分配。

确定性函数返回结构化 outcome/output；引擎校验已声明 outcome 对应的 contract。执行异常、无效输入输出与业务拒绝分开：合法 rejected outcome 可以被接纳，抛出异常或输出违约属于执行失败。失败诊断不回显输入、输出或抛出的任意异常文本。

首期 JSON 契约采用 JSON Schema Draft 2020-12，显式登记 contract ID。使用 AJV 严格校验和 format 校验，不转换类型、不填默认值、不删除额外字段，不进行网络 schema 获取；此切片只允许本 schema 内的片段引用。登记时先校验 schema，保存独立副本；调用时提供独立 JSON 输入副本，结果接纳也保存副本，避免函数修改调用方输入或事后改变已接纳结果。

函数实现注册与定义注册分离。契约注册、定义注册和函数执行均可在无文件系统、无 Harness 的环境独立测试。执行前需要所有引用已解析，不以替身支持宣称真实 Agent 或容器支持。

后续文件和 Agent 切片继续遵循 #9：可写输入工作副本不回写来源；outputs 自动发现候选产物；单正常出口 Agent 正常结束且契约通过后由引擎赋值；多出口用结构化 outcome。文件契约、可信前序执行证据、Runner 和完整 Workflow 不属于本次 JSON 函数切片，不能通过移除此决定到 implemented 冒充整项完成。

### 文件契约与交接切片

文件契约注册与 JSON 契约分开；engine 只处理相对路径、文件/目录类型、媒体类型、大小、数量及可选 JSON 值，具体扫描、复制和摘要由 integrations 的文件存储实现。契约按 rule ID 声明 file 或 tree、相对路径模式、minCount/maxCount、允许媒体类型及单文件 maxBytes；tree 另声明 minFiles/maxFiles。contract 限制整个集合的文件数和总字节，JSON 文件可引用已登记 JSON contract。

模式支持普通相对路径、单段 * / ? 与独占整段的 **；无正则、否定模式或优先级。每个文件或 tree 根只可匹配一条规则，目录树之间及树与文件规则不重叠；否则拒绝歧义。未归属文件拒绝，不隐式丢弃。未归属且只包含空目录的普通目录不作为产物；结构性父目录和明确声明的 tree 内空目录保留，tree 内全部文件按同一规则验证。真实 Codex 工具会留下 .agents/.codex/.git 空目录；参考 Blackbox 只把未归属文件视为违约，避免让运行工具的空目录妨碍合法交付。规则按内容和契约归属判断，不在 engine 中特判 provider 目录名。minCount=0 表示可选，规则不会补造文件。JSON 解析使用严格 UTF-8，schema 只读取显式 JSON 值。

宿主必须先确认生产者已停止，再从宿主控制、无并发写者的目录捕获。扫描不跟随符号链接，拒绝硬链接、非普通文件、越界路径及超限内容；复制时核对读取前后文件事实并计算 SHA-256。验证失败不发布快照。通过后以私有快照 ID 整体交接，下游使用新目录独立副本；重新复制时逐文件验证大小和摘要，不把上一次通过当作本次内容完整性证据。源目录和存储祖先由受信宿主管理，本机实现不承诺抗同权限宿主攻击或跨进程持久恢复。

参考 Blackbox 的角色/目录树约束、复制时摘要和交接复核；不迁移其由 Agent 提交 artifacts 清单的收集协议。媒体分类由本机适配负责，当前实现只承诺列出的类型检测，PDF/图片签名不是完整格式或业务质量验证。通用执行接纳与可信前序记录后续通过接口使用此切片，不在文件校验里加入 Harness 或 Workflow 分支。

### Agent 一次接纳与可信收据

一次 Agent 执行通过 engine 的执行驱动接口完成；宿主显式注入受信驱动，驱动负责把已验证输入快照物化成独立输入并调用具体 Harness/认证/Runner。执行请求只描述本次 Component 标识、身份、用户任务与 outcome 对应文件契约，不取代后续 Workflow 的 Component 定义/编译，也不在这里决定路由。首个文件执行切片的业务结构化内容放 JSON 文件，沿用文件 JSON schema；尚不新增通用内存 JSON 输出协议。

引擎先检查契约引用及本次 Attempt 唯一性。首节点从宿主源捕获输入；后继只能引用本引擎已接纳、同 Run 的前序收据，且输入契约 ID 必须等于前序输出契约 ID，保持整体交接。输入/输出快照描述、任务与身份在异步调用前后由引擎留存副本，不接纳模型提供的收据正文。受信驱动须实际使用传入快照，不允许 Workflow 传任意驱动函数或外部自行报告成功。

接纳同时要求：请求、Runner、Harness 身份一致，进程实际退出 0、停止确认、容器已删除，原始采集完整，Harness 正常终态，认证/执行收尾成功且无诊断，输出通过对应文件契约。单出口仅在通过后赋值；多出口必须有合法结构化 outcome。取消在启动前阻止调用，执行期间交给驱动，不将之后的清理成功升级为原任务成功。失败不产生可信收据，保留执行句柄供停止/清理重试。

收据仅由引擎内部接纳路径创建，绑定 Run/NodeTask/Attempt、Component、实际 Harness/版本/镜像、输入和输出快照描述、outcome 与前序收据 ID。当前用私有内存登记表核验身份并防同 Attempt 重复执行，外部只取得副本；它不是可离线认证的数字签名，也不承诺进程重启后的持久链验证。后续持久化须重新实现登记与完整性边界，不能将任意反序列化正文直接导入为可信。快照生命周期由宿主显式释放，已释放文件不能再次交接；释放不删除历史执行事实。

这些职责参考 Blackbox 的宿主签发收据及前序材料复核，去掉其运行时与文件存储的直接依赖，不将其私有路径、原始日志或认证值带入普通收据。业务 Gate 可检查收据事实，但不通过模型生成的“完成证明”建立信任。

### Workflow 编译与串行控制

Workflow 定义与一次节点执行继续分开。定义包含 id、start、input、命名的终点 outcomes、maxSteps、nodes 及 routes；节点只引用 Component，路由通过 from/outcome 唯一定位，目的地为 node 或 end。Workflow 边界契约使用 kind=json/files 与 id，避免两个契约注册空间恰好同名时误连线；节点仍沿用 Component 的契约引用，由显式安装的执行器解析其具体类别。调度层交换 JSON 快照或后续适配器持有的受信文件引用，不据任意 JSON 文件清单建立信任。

编译器通过只读 Component catalog 和已登记的一次执行端口解析支持范围、实现与契约。启动前拒绝缺失/重复/未知出口路由、错误起终点、契约不一致、不可达节点、未使用终点及非法规模或上限。相等比较包含类别与 ID；需要改变契约时使用 Transform。所有定义取快照；编译计划由本编译模块私有登记，普通 JSON 不能伪造可执行计划。首期节点最多 256、每节点出口最多 32、运行 maxSteps 为 1–10000；这些是资源边界而非隐式业务返修次数。

串行控制只依赖一个节点的执行端口，不解析 Harness 日志、不启动容器、不读取秘密或实际文件。首个适配复用已登记的 JSON gate/transform 函数；Agent、文件、脚本与 Effect 须通过各自明确适配和验证逐步接入，不能因 catalog 接口存在就声称全部支持。

每条路由可选 limit={max,exhausted}，max 为允许沿正常目的地前进的次数（0 表示直接采用 exhausted 目的地）；耗尽目的地同样由用户选择 node/end 并经过同契约检查。按 from/outcome 对每个 Run 独立计数。全局 maxSteps 始终约束启动次数；达到后不启动下一节点，保留最后已接纳输出及原业务 outcome，另记录耗尽原因。返修改入同一节点产生新的 NodeTask 与首个 Attempt，首期不自动重试执行失败。定义可含循环，但不会无限运行。

首期最小控制入口选择 TypeScript 库 API：compileWorkflow 与 start/query/cancel；CLI 定义加载不另列为本项必做范围，符合 #9 按实际实现选择入口形式的要求。start 返回可等待的 Run 句柄，query 返回副本，cancel 只登记请求并通知运行中的执行端口；启动前和执行后都检查取消，取消后不启动后继。正在执行的可信 TypeScript 函数不能被强制抢占，必须等待其返回；不得把取消请求写成实际已停止。执行端口的正常接纳意味着执行已结束，失败须明确 stopped；端口抛出未知异常或 stopped=false 时记录停止未证实的失败，不报告取消完成。已接纳结果的副本、每步身份、路线耗尽记录与最后结果由内存 Run 保留，持久恢复属于后续 Issue。

正常业务 rejected 可正常结束 Workflow；执行失败、身份不符、非法 outcome 或实际契约失败从不沿业务路由推进。每次调用前后独立校验契约，避免可信端口误报成功；错误只公开静态类别和契约位置，不回显任意抛出文本。模拟 Effect 的授权与幂等、Agent 文件前序可信交接仍为本 Workflow 工作项后续切片，不在本次串行骨架内冒充实现。

### Workflow 文件节点与 Agent 交接

参考 Blackbox 对整个流程签发前序凭据、再独立复核材料的做法，Workflow 文件适配维护自己的私有引用登记表。初始输入先按文件契约捕获并绑定 Run；每个接纳节点记录身份、Component、前序引用、输入/输出快照与 outcome。调度层只传不透明引用，普通 manifest JSON、另一个 Run 的引用和已释放引用不能成为输入；公开凭据只是副本，不支持反序列化导入或重启恢复。

确定性文件 Gate/Transform 是宿主显式登记的可信函数，获得独立 input、work、outputs 路径并直接返回 outcome；只从 outputs 捕获候选结果。它们不是安全沙箱，须在 Promise 返回时结束全部写入，不能留下后台写者。真实 Agent 继续由既有 AgentExecutor 和注入的驱动接纳，Workflow 物化已验证前序快照到私有目录，再走其 source 输入路径，并复核 Agent 收据的输入内容与 Workflow 前序一致。Agent 的一次执行收据保留在 Workflow 凭据中；跨 Gate 的来源链由 Workflow 持有，不伪造或导入 Agent 收据。这个有限的重复捕获换取一次执行与流程证据的解耦，后续有性能证据再优化。

Agent 的用户 prompt/config 由宿主绑定具体实现并在编译前预检，不由 Adapter 生成任务。文件适配不知道具体 provider。每次物化重新校验快照摘要；登记引用只证明来源，不能替代真实复制校验。正在使用的快照不能被释放，历史凭据在文件释放后仍可查阅。资源生命周期由宿主显式管理：成功交接先完成执行资源清理；任何清理失败阻止后继，保留当前身份及可重试清理能力，之后清理成功也不升级原节点结果。无法确认停止时保留临时目录，拒绝删除运行所需输入或报告取消完成。

本切片只接入可信文件函数和已安装的 Agent 执行器；脚本、Effect、持久化与完整 Tutor 验收仍独立推进。接口级合成驱动测试不能冒充真实模型执行。

### 确定性脚本节点

脚本作为 gate/transform 的实现方式，与业务 kind 分开。宿主登记 argv、timeoutMs、已声明 outcomes，并注入现有 Runner 的 backend、clock 和原始记录读取端口；编译预检不启动进程。首期只支持显式 argv，不通过 Workflow 数据拼接 shell 命令，也不继承宿主环境或注入认证。Docker 实现继续使用统一 /task/input、/task/work、/task/outputs 和独立可写输入副本。

参考 Blackbox 的命令执行与结果收集分离、严格结果字段/大小/出口检查，但按用户已确认的“确定性代码直接返回 outcome”改用 stdout：仅允许一份 UTF-8 JSON 对象 {schema:"agentflow-script-result/v1",outcome:<已声明出口>}，上限 64 KiB，单出口也显式返回；stderr 是日志。该协议不包含产物清单或文件路径，业务文件始终从 outputs 自动发现并校验。非零退出、超时、取消、停止/清理未证实、截断/不完整原始记录、无效协议均不得接纳或走业务路由。

脚本一次执行与文件契约接纳分开。核心脚本执行器不读宿主文件，由注入的记录读取端口读取并核对完整 stdout；本机适配使用不跟随链接的有界读取。Workflow 文件适配复用既有引用、文件捕获和清理机制，保留脚本实际镜像/退出事实及前序来源。停止或释放失败保留原身份与恢复句柄，后续清理不升级原结果。此切片不启用生产 Effect 或把宿主可信函数当成不可信脚本沙箱。

### 模拟 Effect 与一次授权

Effect 执行器独立于 Harness、认证存储、Runner 和 Workflow 调度。首期通过显式安装的可信服务适配器验证 dry-run/apply，默认 dry-run；模拟目标服务只写进程内内存。业务身份由服务适配器提供，业务凭据留在适配器私有闭包，不进入定义、输入、审批对象的公开正文或收据。引擎只处理非秘密身份标识。

采用 Blackbox 的一次授权和上下文收据检查：宿主针对已验证的 Component、Run/NodeTask/Attempt、模式、目标、幂等键及完整输入签发不透明授权能力；其私有登记绑定规范化 JSON，不能从 Workflow JSON 或序列化副本导入。每次 apply（包括已完成结果复用）都须匹配授权并一次消费；dry-run 不接受授权，也不占用真实操作幂等记录。宿主授权回调是明确安装的控制能力，不是模型输出里的字段。

每个 EffectExecutor 中幂等键唯一，关联 Component/实现、业务身份、目标及完整输入，规范化对象键顺序。相同键不同请求明确冲突；相同已完成请求重查收据与输出契约后复用，标记 already-applied，不再次调用适配器。第一次真实调用前同步占位，重复并发不重复执行。适配器抛错、收据上下文不匹配或实际写入后的输出不合约，记录 unknown；同键后续请求被阻止，不能删除占位后重发。未安装持久日志时上述占位仅属于本实例；安装持久化工作项的 EffectRecordStore 后，实际调用前还须确认唯一耐久占位，回执耐久提交后才接纳。新进程复用仍要求本次显式授权，不恢复旧授权对象。操作恢复语义由持久化决定负责，不承诺跨崩溃 exactly-once。

收据包含 schema、宿主请求标识、Component、mode、target、key、serviceIdentity、status 与可选外部 reference；接纳必须匹配实际上下文及对应输出 contract。simulated/applied/already-applied 是三个显式业务出口，执行失败不作为业务出口路由。unknown 或仍在进行的操作不能报告取消完成；已经写入后的取消不回滚实际动作。输入、授权范围、适配器请求及公开结果互相取副本。首个 Workflow 适配使用 JSON contract；文件到 JSON 的消费侧转换是后续显式 Transform，不往文件清单或模型自述里嵌入授权。

### 文件到 JSON 的显式 Transform

消费侧可通过专用 Transform 从文件产物生成 JSON 输入，不能把文件引用直接当成 JSON 业务对象。适配器先从现有文件 catalog 核验同 Run、契约和仍可用的私有引用，重新复核摘要并物化独立副本；可信转换函数读取副本及来源事实，返回 outcome/output，输出再按对应 JSON contract 验证。输入与输出契约类别不同，因此本适配器内输入文件 ID 与 JSON 输出 ID 不得重名，编译前拒绝歧义。

转换接纳后，适配器私有登记身份、Component、前序文件引用、输入 manifest、outcome 和精确 JSON 输出；公开查询只给副本，不导入序列化记录。宿主业务授权策略可以核对已登记输出及前序 Gate，再签发 Effect 能力；生成的 JSON 自述不是授权来源。临时目录清理完成前不发布转换结果，清理失败保留恢复能力。业务文件摘要可进入 Effect 输入，以让同键不同文件内容也明确冲突；不能只靠相同文件名或评分总数判定相同操作。

Tutor 合成样例放在 examples/tests，定义材料、候选评分、确定性 Gate、用户选择的 Fixer/次数、最终转换和模拟发布。参考旧流程的来源摘要、覆盖/评分/证据检查和最终 Gate 收据，不移植其固定业务角色到核心，也不把合成模型替身当成真实学生批卷验收。

合成发布的幂等输入包含真实内容摘要，不包含每次运行新生成的文件引用、Run ID 或转换身份，以允许相同内容跨 Run 复用已确认结果。宿主策略另外核对当前 publish Attempt、私有转换记录和实际 Gate 来源；来源约束不依赖业务 JSON 自述。原始材料摘要由每个 Run 的宿主输入捕获提供，Agent 的 revision 不决定返修计数。样例中的评分规则和固定答案均留在消费侧。

真实模型验收复用同一个批卷应用，通过宿主注入 AgentExecutionDriver 工厂、Component/prompt/config 绑定及 Workflow 定义选择真实或合成实现。共享批卷应用不构造具体 Harness 或读取凭据；真实 Codex 组合入口另行使用现有认证 Runner。确定性 Gate 和发布策略不会因实际驱动而切换。真实运行保留接纳的业务产物及来源证据，清理失败不通过直接删除根目录掩盖；没有实际调用模型的合成测试不计为真实验收。

### 扫描件批改与复核消费端

同一最终验收接入独立 Marker、Reviewer 以及用户指定的修复 Agent。各自只交付契约文件；Candidate Gate 复用 Tutor 业务 validator，Final Gate 除评分结构外核对复核阈值、每项检查、初始与最终候选哈希，并从当前 TypeScript 文件 catalog 的实际前驱收据确认复核输入来自可信 Gate。Agent 可以修改自己的输入副本与候选输出，但不能改变本 Run 的原始来源或重写可信复核输入来放宽阈值。

返修通过用户传入的 Agent 绑定和有限 Workflow 路由表达，不在引擎固化角色或两次上限。消费端不使用旧 Review Input 的固定两轮 repair 扩展；用当前失败 Gate 的报告提供反馈，重新绑定当前候选，实际计数由 Workflow 控制。沿用 Tutor Schema 的 /input 描述符作为逻辑路径，由消费端明确映射到统一 /task/input，不新增实际挂载目录。

通过 Final Gate 后，消费端只从该次实际通过的结果导出 source/candidate 供现有报告应用消费；拒绝不能调用该交接。Marker/Reviewer 与报告保持应用级组合，暂不宣称这条宿主工具链具备持久 Worker/Docker 支持。初次集成允许明确合成 Driver 验证来源、拒绝、返修、报告串接；实际模型调用及学生评分质量仍须另验收。此为既有 #9 和最终验收授权范围的实施细化，主责及审阅情况同上。

真实合成验收入口可由调用方显式选择上一轮已释放的失败执行草稿，连同同一原始来源作为新 Marker 的普通输入。模型可以基于副本修正，原草稿留存；这不是旧执行恢复或接纳，不复制旧可信收据。新的正常 Harness 终态、候选 Gate、独立复核和 Final Gate 缺一不可。草稿路径选择与任务说明仍在消费端，核心不固化“超时就接纳文件”或自动挑选历史候选；示例没有通用草稿管理和跨进程恢复能力。

实际多页照片在 Tutor 原有 EXIF/RGB/PNG 归一化后明显大于合成样例。消费端允许调用方声明 maxSourceBytes，默认仍为 128 MiB、上限 512 MiB；批改与报告分别按该值验证 source 树，其他文件/总量限制继续生效。选择保留原始分辨率并显式设置预算，而不是为了通过样例限额降低手写证据质量。Agent 时限同样来自受信宿主配置；小型合成入口仍为 180 秒，完整学生入口须明确提供有界时限，不让任务产物自行放宽。用户已指定从 Downloads 选择 Extension 1 作答用于当前 Codex/OpenAI 验收，来源、模型与实际结果留在私有验收记录，仓库只记录脱敏能力证据。

存储层与业务契约预算分别生效：FileArtifactStore 的 maxTotalBytes 由受信构造方设置，默认 256 MiB、硬上限 1 GiB；复制及直接物化捕获均取该预算与 contract 总量的较小值。构造时捕获数值，后续修改 options 不影响运行。单文件 64 MiB、JSON 1 MiB 及完整性/链接防护保持。Tutor 消费端按来源预算加 128 MiB 交付余量配置本机存储；持久 FileArtifactArchive 仍为原 256 MiB，未验证这条多页消费链的持久恢复。参考旧 Tutor prepare_marking_source 的 512 MiB 输出预算，避免对特定试卷取消通用边界。

DockerBackend 输入复制预算与存储预算独立，maxInputBytes 默认 256 MiB、最高 1 GiB；直接来源和 Artifact 物化来源使用同一预算，并保存在既有执行定义中。认证 Runner 的宿主组合显式透传，不将该字段开放给 Agent 任务配置。准备阶段未建立认证副本且 binding 已释放的 not_prepared 属于收尾完成，不代表 Harness 成功；业务接纳继续要求正常终态。消费端按逆序先清理失败下游，再释放其借用的上游文件；清理未完成时验收摘要保持失败。Blackbox 同样将失败收尾放在容器结束后的认证占用范围内，参考行为而非复制其结果协议。

默认 256 MiB 在执行定义中保持旧有隐含表示，显式设置同一默认值也不增加字段；只有不同预算记录 maxInputBytes。这样未启用新预算的调用保留原定义指纹，避免纯配置序列化变化导致旧持久任务恢复被拒绝。非默认预算仍参与严格定义比对，恢复时不能静默改变容量；这不迁移队列开发 v1/v2 索引。

复杂消费端可以把已安装的纯确定性业务 validator 作为输入辅助工具供 Agent 自检，避免模型重写校验逻辑。该副本是普通输入，不具备签发可信 Gate/收据的能力；宿主仍调用独立安装的原代码并验证输入与前驱。显式学生草稿只在新任务包中作为未接纳输入，既有源文件不变；输出位置用完整路径列出，不能把 source 子树当成候选目录。此为既有实际批卷验收的消费侧实施细化。

报告遇到 MISSING 空分值时不默认补零。沿用已安装 Tutor 的 report_completeness：调用方提供明确用户确认，绑定 job、候选文件 SHA256 和精确缺失 item IDs；宿主校验后只生成指标/渲染投影视图，原始候选及复核证据保持不变。报告 Agent 可读该确认和投影但不能修改；渲染阶段重新从原候选和受信配置计算并核对投影。UNREADABLE 或其他尚未解决的空分值继续失败。2026-09-10 用户已明确确认选定16张照片包含全部作答，并允许按此规则报告。公式 PDF 的文本提取可能丢失数学符号，消费端可显式追加来源页面图像和文件角色说明，批改/复核仍各自判断原始证据，核心和 Adapter 不加入试卷专用评分规则。

已通过批改的结果可以作为单独报告应用的显式输入；上游真实批改/复核证据由调用方保留，报告入口不重新批改、导入旧引擎收据或冒充持久恢复。失败报告草稿只能作为新输入中的普通参考，新 Reporter 须正常完成且重新通过报告 Gate。Reporter 保持 source/candidate/report-source 原有顶层布局，只新增 report-candidate；消费端按角色说明目录职责，不能将可信定量来源误移为另一种目录。Codex 图片遵循现有 CLI 的单一变长 --image 参数，64附件仍服从 Runner 的128参数及原长度上限。
