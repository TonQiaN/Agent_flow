# 认证元数据、秘密与独占执行绑定分离

创建于 2026-09-09。

## 结论与边界

按 #11，认证是宿主控制面：Profile 只存服务、方法、endpoint、已授权目标、credentialRef 与容量，Workflow 仅引用 Profile。秘密存储不挂给 Agent；Adapter 只声明需要的材料和环境。Effect 业务身份独立。

首个 Codex 订阅组合先支持单份 credentialRef 的独占使用（capacity=1）。不同 Profile 指向同一 credentialRef 共用一个跨进程锁；不从远端账号信息猜测跨文件别名。凭据导入只能明确选择录入内容或受控宿主文件之一，冲突即拒绝，绝不继承终端环境。存储目录和文件要求当前 UID、私有权限、非链接普通文件；读取和更新均验证元数据及格式，错误不回显值。

秘密采用带身份、generation 与 revision 的私有记录，更新写临时文件并原子替换。使用租约持有锁并记住读取版本；调用者提交工作副本时必须显式携带原 revision，存储同时核对 generation/revision 与新内容格式，禁止旧副本无条件覆盖。删除后重新配置产生新 generation，避免 revision 重置后误认旧登录。工作区只有本次所需材料，Harness 会话/数据库不共享。后续绑定将受支持的刷新结果带回此接口，不把复制后覆盖当成并发协议。

跨进程锁采用宿主私有目录的排他创建，有限等待；同一进程内异常通过显式 finally 释放。不能因锁超时或宿主 PID 不存在就推断旧容器已停止，崩溃后的使用恢复须与 #13 对账。管理替换/删除也取得同一锁；删除是本地删除，不宣称远端撤销。初始不自动恢复损坏或删除的凭据；安全备份恢复在后续认证切片按已识别格式和删除语义验证，不能虚构已支持。

检查状态仅报告本地配置、身份和 revision；远端认证、订阅有效性及额度均为 unknown，除非记录实际远端证据。普通序列化只显示元数据，秘密只能通过显式受信调用获取，不能落入普通错误和结果。

endpoint 与允许目标由宿主配置；Codex 订阅首个组合只接受实际官方认证/请求目标，不支持任意覆盖地址。受控 egress 必须在真实请求前接通并验证直接外连不可用，尚未接通时不将 offline Runner 改为宽松联网冒充完成。

首版 egress 使用精确 DNS 主机名与端口 443 的宿主列表，解析及实际拨号都受同一策略约束；只提供公网 IPv4 隧道，未知/私有地址与 IPv6-only 目标失败。代理没有秘密和业务数据目录，只转发不解密的连接。Profile/绑定将提供经验证的允许目标；Runner 环境中直接配置列表的基础测试不证明 Profile endpoint 管理或真实服务认证已经完成。

运行凭据绑定是独立 integrations 能力：宿主在执行前取得 credentialRef 租约并固定身份与原 revision，容器后端只提供新建的私有 state 目录及非秘密路径环境。Invocation 不包含秘密或宿主凭据路径，Adapter 不读取存储，Runner 不判断服务类型。绑定按固定相对位置写入 0600 工作副本，拒绝链接、共享文件及不安全父目录。一个绑定只服务一个 ExecutionResource，初始化与收尾串行化。

收尾消费宿主 RunnerResult，核对执行身份和资源；只有停止已确认且任务/代理清理成功，才读取工作副本、条件回存并移除副本，最后释放租约。取消或执行非零不等同凭据未刷新，仍需在满足停止和清理条件后处理；未知停止或清理失败保留租约，等待可信恢复结果，不能用传入布尔值跳过。格式损坏不覆盖原存储，报告刷新失败；副本无法安全移除时保留租约。初始化前可放弃绑定，一旦初始化开始则必须凭执行结果收尾。此接口本身不证明 provider 格式、真实远端刷新或整个 Agent 接纳已实现。

首个实际组合仅接纳 Codex 管理的 ChatGPT auth.json（auth_mode=chatgpt、完整 token bundle），排除 API key 与外部 token host 模式。格式 codec 只做本地检查；刷新需保留原 account_id，管理 configure 可经显式授权替换账号。Profile 明确 id、service、method、credentialRef、official endpoint 和 capacity=1；当前组合不接受任意地址、额外字段或隐式环境凭据。官方目标限定为 chatgpt.com 与 auth.openai.com，Codex 自己进行远端刷新。

秘密脱敏由绑定侧提供：只在受信内存中记住本次初始及刷新 token 和已知账号标识，普通事件经过替换；格式或脱敏失败时不发布消息 payload。原始日志仍私有，不能把值替换宣称为任意编码或业务 PII 的完整过滤。旧系统导入属于私有验证桥接，在原系统的独占锁期间读取/运行/同步刷新，不能使两套系统各自持锁却同时使用同一 token。产品实现不依赖旧系统模块。

### Claude 订阅执行细化

Claude 2.1.226 使用独立 `.credentials.json`，只接纳 `claudeAiOauth` 内固定版本的字段；不导入同文件中的 MCP、API key 或其他服务秘密。codec 验证 access/refresh token、毫秒过期时间、scope 和可选刷新过期时间/clientId/订阅元数据；本地检查不证明远端有效。该格式没有稳定 account_id，不能照搬 Codex 的账号一致性结论：刷新保留 clientId，禁止无效状态重新变成有效 bundle，账号归属仍需远端证据。

实际 CLI 会在 invalid_grant 后把 accessToken、refreshToken 清空并把 expiresAt 置零。这个明确的无效状态需要条件回存，不能作为破损 JSON 丢弃后恢复旧 token；随后执行在取得租约后、写入工作副本前拒绝，需要用户重新配置。其他畸形结果仍保持旧存储并报告刷新失败。此语义与旧系统只恢复无法解析的文件相容，不扩展为自动登录或任意凭据恢复。

绑定支持固定相对文件名中的单个前导点，继续拒绝 `.`、`..`、绝对路径、空段、反斜线及不安全父目录。Docker 的 state 环境校验保持原边界；Claude 独立组合把非秘密的固定管理路径/开关作为 `env` 程序的分立 argv 参数注入，不接受用户任意环境覆盖。所有源秘密仍只经独占绑定进入本次私有 state。

两个订阅组合共享 integrations 内的执行收尾和文件交接机制，通过独立配方注入版本解析、Adapter、Profile、脱敏和固定调用材料；engine 和通用 Docker 后端不增加 provider 条件分支。Claude 请求目标限定 api.anthropic.com、platform.claude.com；受控代理与实际工具隔离必须分别验证，合成 CLI 通过不能视为真实 Claude 模型或 OAuth 成功。

## 方案考量（alternatives）

| 方案 | 收益 | 代价 | 取舍 |
| --- | --- | --- | --- |
| credentialRef 级文件锁 + revision 更新 | 可跨进程协调，避免别名重复占用和旧快照覆盖 | 首个订阅并发限制为 1 | 先采用并明确范围 |
| 只用内存计数器 | 简单 | 多个 Worker 不共享约束 | 用户已排除 |
| 共享整个 Harness 状态目录 | 刷新直观 | 临时二进制/数据库/会话互相干扰 | 用户已排除 |
| 复制认证后无条件覆盖 | 容器内易写 | 旧任务可覆盖新刷新 | revision 和独占租约前置 |
| 自动按过期时间回收锁 | 不易留下等待 | 旧容器仍可能刷新，产生双重使用 | 先核实执行停止，后续恢复协调 |

## 影响与验证

先验证秘密来源、权限与链接、身份不匹配、格式失败、不回显、跨进程独占、等待、异常释放、更新冲突及管理协调。真实订阅复用、刷新、绑定清理、受控网络与 Agent 文件权限尚须联合 Runner/Codex 验证；API key 管理、其他组合和安全恢复仍在 #11 范围内，部分实现不关闭整项。

## 重开条件

真实 Harness 需要更高订阅并发或特定刷新方式时，以实际版本行为调整绑定，保持元数据/秘密/执行环境解耦。需要多机或外部保险库时另行界定范围。

## 确认与变更留痕

- 2026-09-09：用户已确认 Profile/秘密/绑定、来源冲突、刷新隔离、endpoint 与容量边界并授权开发。首期独占与 revision 检查属于已授权实现细化，尚未验证真实刷新。旧专用 Codex 凭据存在且安全属性符合读取条件；未将其内容输出或提交，也未把存在等同远端有效。
