# 功能模板补充场景与行为契约

创建于 2026-09-08。

## 结论与边界

功能模板描述新增或改变的产品能力，目标文件为 `.github/ISSUE_TEMPLATE/feature.yml`，标题前缀为 `[功能]`。本决定只负责功能相对 [共通规范](../README.md#d-20260908-issue-template-common) 的差异；选类与拆分归 [分类决定](../README.md#d-20260908-issue-classification)。实现载体是代码、配置或 Prompt 不改变归类依据。

### 相对共同基线的增删改

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写 | `problem`：问题、场景与目标 | 保留 textarea 与创建必填意图。写谁在什么场景遇到什么限制，本次新增或改变什么能力；用用户结果说明动机，避免只列技术或文件名 |
| 增加 | `behavior_contract`：行为与接口契约 | textarea，创建必填。用输入→输出、正常/边界/失败例说明行为；适用时补接口、读写副作用、兼容与权限。新功能没有历史行为可直接照搬，需要明确可实现的契约 |
| 删除 | 无 | 功能也需要主责、范围、交付物、验收、依赖、决定及续接；不为缩短表单删除这些职责 |
| 保留并解释 | `acceptance` 等其余七字段 | 字段结构沿用共同规范；验收填写范围内的可观察行为及验证方法，交付物不只写“代码已提交” |

完整表单共九个输入块；behavior_contract 放在 problem 后，其余顺序沿用共通规范。新增字段不要求附完整实现设计：接口尚待敲定时写明问题、影响和处理位置，实施前按预检处理必要未知。

### 验收与例子

功能验收核对正常结果、关键边界/失败情况及实际兼容影响；测试程度随具体风险确定，不能以本模板要求所有功能运行同一套测试。必要研究与决定可在同项推进，最终仍需交付承诺的产品结果。独立只交证据或选择结论的工作按分类决定处理。

例如“只读展示一次运行的外围时间回放”：描述输入在何时提交、任务何时开始、输出何时返回；停在返回前的时间点不显示未来结果，回放不产生新运行或外部动作。明确第一版只读、记录外围时间与输入输出；关联当次镜像环境和节点能力配置，排除容器内 agent 会话/工具轨迹。这是基于已确认产品方向的填写例子，不表示回放已实现，也不把该例的字段强制用于所有功能。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 只用共通 problem 与 acceptance | 字段少，已有表单接近此方式 | 用户目标容易直接跳到“实现完成”，遗漏输入输出和失败边界 | 独立增加行为契约 |
| 场景改写＋一个行为契约块 | 区分动机、行为与验收，仍可简短填写 | 和验收有部分关联，需要避免重复长文 | 采用；契约写预期行为，验收写如何证明 |
| 将每种接口、权限、兼容、错误都设独立字段 | 大功能覆盖全面 | 小功能出现大量不适用项，增加创建负担 | 按条件合并在行为契约或范围内 |
| 功能模板强制完整技术方案 | 便于直接编码 | 过早锁定实现；把必要研究变成填表前置工作 | 创建时描述结果，必要取舍在实施前补齐 |

## 影响与验证

保留 feature.yml 路径与旧共同 ID，实施时增加 behavior_contract、共同交付物和续接字段。验证九字段完整、problem 的差异明确、共通字段未偏离；用上述回放例及一个配置/Prompt 行为改进例核对可填写性。例子必须区分假设数据和实际验证；当前已用完整表单进行填写演练，产品功能未运行。

本轮文本核对见 [设计验证记录](../../../../docs/validation/2026-09-08-issue-template-decisions.md)，完整表单的本地验证已执行，默认分支入口核对尚待完成。

## 重开条件

真实功能反复遗漏特定契约、行为字段与验收大量重复，或小改进需要填写过多不适用内容时，带实例调整专用字段。不能仅因增加一个 Harness 或文件类型再复制功能模板。
