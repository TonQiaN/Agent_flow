# 用五类表达 Issue 的主要交付目标

创建于 2026-09-08。

## 结论与边界

Issue 采用功能、缺陷、研究、决策、维护五个主类型，按主要完成条件选择一个。工作性质与交付物分开：任何类型都可能产生决定、代码、配置、说明或验证记录，不能用“有没有产品代码”判断工作是否成立。

| 类型 | 主要问题与完成条件 | 典型范围及边界 |
| --- | --- | --- |
| 功能 | 新增或改变什么产品能力；完成已约定行为及验证 | 新增只读外围回放、节点能力配置、独立 Harness 模块。必要研究和方案选择可以在同项完成 |
| 缺陷 | 什么已约定行为失效；恢复契约并验证相关回归 | 假设已有回放却提前显示未来输出。根因未知或暂未复现仍可作为缺陷跟进 |
| 研究 | 哪个未知事实需要证据；交付有界结论、证据限制和去向 | 验证指定 DSH 版本的节点插件隔离。结论可以不支持原设想，证据不足不能伪装成可行或失败 |
| 决策 | 团队要选定什么；形成自足的正式决定、确认范围和落实交接 | high level 范围、支持矩阵或方案选择。可仅以决定验收，采纳不表示产品已实现 |
| 维护 | 要落实什么工程、文档或协作改进；交付约定文件或工程结果并验证 | Issue 模板、开发指令、依赖升级、既有契约内重构；名称“维护”不豁免非平凡改动的流程 |

主类型不是阶段。以交付模板为目标的 Issue #6 在研究阶段仍是维护；不能为每次 AI 会话、调研步骤、工作分支或 PR 自动新建 Issue。若研究结果决定是否继续实现、不同主责可以独立交付、存在明确阻塞或不同验收时间且独立交付有价值，再考虑拆分。父项仍有主要类型并验共同结果，父子关系与阻塞关系分别说明。

模块、优先级、版本、进度、父子关系和关闭原因各自表达，不增加 Prompt、文档、测试、性能、发布、Epic 等平行主类。修改 Prompt 以新增业务行为属于功能，修复违反既有输出契约的 Prompt 属于缺陷，改善团队开发用指令属于维护。先核对既有契约，再判断新增行为、证据问题、方案选择或工程交付；混合工作按最终承诺归类。

### 分类入口与完成事实

首版使用五个模板入口及 `[功能]`、`[缺陷]`、`[研究]`、`[决策]`、`[维护]` 标题前缀。人参与整理时核对类别与正文目标；前缀不是不可修改的机器约束。不同时建立另一套必选类别标签或组织级类型，模块/优先级标签按实际筛选需求处理。

有主责、明确产出和结束条件的研究或讨论可以立项；开放聊天、一般问答、重复需求、同项交接优先留在已有沟通或工作项中。研究/决策仅在自身约定交付全部满足后结束；若还承诺实现文件，不能只凭决定关闭。取消、重复、延期、无法复现的处理要说明事实和去向，不写成已实现或已修复。具体模板验收解释分别归各类决定，PR 合并与关闭条件仍归 [开发流程决定](../README.md#d-20260907-development-workflow)。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 功能、缺陷、维护三类起步 | 入口少，已有表单可用 | 独立证据研究与范围/方案确认混入维护，交付终点不清楚 | 保留其历史起点，按实际需求扩展 |
| 研究与决策合并，共四类 | 少一个入口，探索工作集中 | 回答未知事实与选择方案所需字段、结束条件不同 | 当前分开；实际反复难以区分时再评估 |
| 五类主工作项，交付物独立 | 对应不同完成条件，保留原三类并补研究和决策 | 需解释交叉场景，防止阶段拆项 | 采用；不是宣称五类在所有团队最优 |
| 按 Prompt、文档、测试、发布等继续细分 | 名称直接，局部检索方便 | 混合实现载体、目标和结构层级，易多头归类 | 当前通过范围与条件信息表达 |
| 只靠标签组合、不保留主类 | 自由度高 | 缺少统一的模板入口和主要验收目标 | 首版采用主类；后续检索需要再扩展标签 |

## 影响与验证

分类选择集中归本决定；[共通规范](../README.md#d-20260908-issue-template-common) 负责共同字段、存放与同步，五类差异分别归各自决定。原开发流程决定只保留阶段与职责，不再维护另一套类别定义。

落实时用新增功能、未知根因 Bug、Container 能力研究、仅决定的 high level 确认、模板维护及跨阶段混合工作检验归类；验证父子拆分不会成为第六类、取消不会成为完成事实。五类正式表单、使用指南及本地填写演练已落实；默认分支入口核对尚待完成，长期使用效果尚未测量。本轮正文核对见 [设计验证记录](../../../../docs/validation/2026-09-08-issue-template-decisions.md)。

## 重开条件

出现有具体例子的选类冲突、研究与决策长期无法区分、不同类别反复需要相同专有验收，或某类真实工作无法合理归入时重开。不能仅因新增工具、文件类型或换一个 AI 就增加主类。
