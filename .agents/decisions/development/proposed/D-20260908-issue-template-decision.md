# 决策主 Issue 说明当前情况与需要作出的选择

创建于 2026-09-08。

## 结论与边界

本决定负责 `.github/ISSUE_TEMPLATE/decision.yml` 相对 [主 Issue 共通规范](../README.md#d-20260908-issue-template-common) 的差异。表单帮助制定者表达需求，执行方案由对应负责人负责；本决定的字段约束仅适用于主 Issue。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的变化

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写或保留问题提示 | `problem` · 当前情况与需要作出的选择 | 说明为何现在需要选择、影响谁、已经确认什么、还希望解决什么问题。 |
| 去除旧方法要求 | `options`、`impact` | 建项不要求提前写候选比较、推荐方案、落实路线或重开步骤。已确认约束与当前影响归 scope / decision_context，期望得到的选择结论和适用边界归 problem / acceptance。 |
| 沿用共同字段 | 除 problem 外八项共同字段 | 按共通决定表达领域、责任、要求与实际进展，不换名加入方法要求 |

完整表单共 9 个输入块。标题前缀、保留字段的 ID 和交付物选项继续沿用；历史 Issue 不批量回写。

### 完成条件

正式决定可以是唯一交付物，但最终正文须满足既有内容规范：真实比较与选择理由、适用边界、必要未知和确认依据自足。要求最终成果有依据，不等于要求需求制定者建项时已经作出选择。只有一种合理方案不编造比较数量；关键证据缺失时如实保留待定。采纳与后续实施分别验收，承诺模板或代码时不能仅交决定关闭。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 沿用研究模板要求实验 | 探索边界清楚 | 纯范围选择未必需要实验 | 决策主表聚焦需要作出的选择 |
| 只写推荐方案就结束 | 简短 | 依据、未选理由和影响丢失 | 最终正式决定仍须自足 |
| 至少三个候选和多名批准人 | 形式整齐 | 容易编造比较并增加等待 | 无数量门槛，记录实际确认 |
| 建项填写 options 与 impact | 旧版利于提前比较和交接 | 把选择任务预先交给需求制定者 | 删除两块，最终决定保留必要比较与后续归属 |

## 影响与验证

同步当前表单、共通说明与差异索引；核对输入块数、问题职责、方法要求的移除和实际需求的去向。主 Issue 填写案例应能在不知道实现方法时表达完整需求；子项不提供示范正文。#6 旧版的演练和线上检查保留为历史，本轮结果及未覆盖范围见 [本轮验证](../../../../docs/validation/2026-09-10-main-issue-templates.md)。

## 重开条件

真实主 Issue 反复遗漏必要事实、成果质量或边界，或共同提示造成无法表达的需求时，带实例修订原决定。子项是否提炼模板依据共通决定中的实践条件，不因主表更新自动推广。
