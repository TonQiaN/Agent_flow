# 决策模板说明待选问题与期望结果

创建于 2026-09-08。

## 结论与边界

决策模板用于团队需要作出选择的工作，目标文件为 `.github/ISSUE_TEMPLATE/decision.yml`，前缀为 `[决策]`。制定者说明当前情况、为什么需要选择、希望该选择解决什么及已有约束；候选方案和比较是执行中形成的内容，不是创建 Issue 的前提。沿用 [共通规范](../README.md#d-20260908-issue-template-common) 和 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的差异

| 字段 | 处理与内容归属 |
| --- | --- |
| `problem` | 标题为“当前情况与需要作出的选择”；说明当前问题、选择目标及其用途，不要求推荐方案 |
| `options` | 删除候选方案与比较依据输入；不预先限制执行者要考虑哪些路线，也不强迫创建者先完成方案比较 |
| `impact` | 删除影响、落实与重开计划块；已知需求边界归 scope，期待的选择结果归 acceptance，实际取舍与后续影响进入正式决定 |
| 其余共通字段 | 沿用共通规范；共九个输入块 |

若仅需敲定产品范围或方案边界，可以只交正式决定。结果仍须说明最终选择、真实理由、适用限制及必要确认；正式决定的 [内容规范](../README.md#d-20260907-decision-record-content) 继续适用，不因删去 Issue 的预设方案栏而省略实际取舍理由。

已有明确要求在范围或相关决定中保留，尚待选择的内容写成问题。完成事实区分已采纳结论、未解决问题与尚未落实事项；不以决策 Issue 关闭自动变更产品实现事实或 [决策生命周期](../README.md#d-20260907-decision-lifecycle)。若还承诺模板或代码，仍需达成这些结果。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 创建时必填 options 与 impact | 鼓励真实比较并提前想到交接 | 容易在问题尚未澄清时先锁定候选与实施路线，重复正式决定内容 | 原方案曾采用；本次移除预设方法栏 |
| 只写推荐方案 | 启动快 | 需求和判断标准不清楚，提议容易被当作约束 | 用当前情况与期望选择结果表达 |
| Issue 说明待选问题，正式决定保存形成的取舍 | 保留探索空间，事实和理由有唯一归属 | 交付时仍须有足够依据并明确影响 | 采用 |
| 固定候选数量或审批人数 | 形式容易检查 | 可能虚构比较或增加无依据的门槛 | 不设数量配额，按实际讨论记录 |

## 影响与验证

用仅交正式决定的产品范围确认检验：不知道候选方案仍能说明选择目标、约束及完成结果。再核对尚缺关键依据与仍承诺实现产物的情况，不能提前宣布完成。

此前版本的字段与线上检查见 [2026-09-08 实施验证](../../../../docs/validation/2026-09-08-issue-templates.md)。本次改版由 [Issue #21](https://github.com/TonQiaN/Agent_flow/issues/21) 跟进，当前待完成新版交付与默认分支核对，移回 proposed；旧验证不作为新版本已生效的证据。

## 重开条件

真实填写仍需反复追问当前情况或期望结果、方法约束转移到其他字段、必要事实丢失，或无法判断完成边界时，带具体例子修订。不能为恢复旧字段数量重新添加方法栏。
