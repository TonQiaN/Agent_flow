# 研究模板说明未知问题与期望结论

创建于 2026-09-08。

## 结论与边界

研究模板用于需要减少不确定性的工作，目标文件为 `.github/ISSUE_TEMPLATE/research.yml`，前缀为 `[研究]`。制定者说明当前知道什么、尚不清楚什么、希望弄明白什么以及答案有什么用途。方法由研究执行者选择；不能在建项时把取证路线、比较基线、实验工具或步骤写成固定要求。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)，共同表达见 [共通规范](../README.md#d-20260908-issue-template-common)。

### 相对共同基线的差异

| 字段 | 处理与内容归属 |
| --- | --- |
| `problem` | 标题为“当前情况与希望弄清的问题”；说明已知情况、关键未知及结论用途 |
| `evidence_plan` | 删除方法、假设、比较与证据计划输入；已有事实归 problem，执行方法不迁入其他栏 |
| `stop_rule` | 删除独立块；研究范围及实际投入约束归 scope，期望结论和可接受的不确定性归 acceptance，不要求制定者先设计研究流程 |
| 其余共通字段 | 沿用共通规范；共九个输入块 |

研究可以得到支持、不支持或有界不确定结论，完成条件看问题是否得到有依据的回答。关键问题仍缺依据或必要讨论时，不因花完预算或完成一套步骤就视为完成；不可接受的不确定性需要继续澄清目标或安排后续归属。

研究成果应说明依据、适用限制和未解决问题。具体资料、实验方法及实际条件在成果中如实交代，这是结果可信度的要求，不是 Issue 制定者必须提前提供的方法。研究可以只交正式决定，但正文须自足；研究完成不意味着产品能力或建议指令已部署。

例如 #20 关心现有 AGENTS.md 的必要性、有效性和协作成本，期望得到可供人判断的保留或调整结论。Issue 保留这些问题与质量要求，不预先指定逐项审计表、对照夹具、工具实验顺序或必须采用的改写方案。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 方法、比较计划与停止条件分别必填 | 提前约束研究投入，提醒提供证据 | 制定者尚不清楚如何研究，容易限制执行者与 AI 探索；与范围及验收重复 | 原方案曾采用；按 #20 审查反馈移除方法输入 |
| 只写一个研究主题 | 输入简短 | 难理解为何研究及需要什么回答 | 不采用；仍须说明现状、关键问题与结论用途 |
| 问题、真实范围和结论质量限定交付 | 保留方法自由，同时能判断结果是否有用 | 需要诚实说明不确定性，不能用报告数量代替回答 | 采用 |
| 用预算耗尽或完成固定实验作为验收 | 终点容易计数 | 执行过步骤不保证解决问题 | 按约定结果验收，实际预算仅作为真实边界 |

## 影响与验证

用 #20 以及“结论为不采用”“尚缺关键依据”的情形核对。检查无需预写方法即可完整建项，否定结论不会被误判为失败，证据不足也不会因做过步骤就算完成。具体研究不在本次模板验证中执行。

此前版本的字段与线上检查见 [2026-09-08 实施验证](../../../../docs/validation/2026-09-08-issue-templates.md)。本次改版由 [Issue #21](https://github.com/TonQiaN/Agent_flow/issues/21) 跟进，当前待完成新版交付与默认分支核对，移回 proposed；旧验证不作为新版本已生效的证据。

## 重开条件

真实填写仍需反复追问当前情况或期望结果、方法约束转移到其他字段、必要事实丢失，或无法判断完成边界时，带具体例子修订。不能为恢复旧字段数量重新添加方法栏。
