# 研究主 Issue 说明未知问题与期望结论

创建于 2026-09-08。

## 结论与边界

本决定负责 `.github/ISSUE_TEMPLATE/research.yml` 相对 [主 Issue 共通规范](../README.md#d-20260908-issue-template-common) 的差异。表单帮助制定者表达需求，执行方案由对应负责人负责；本决定的字段约束仅适用于主 Issue。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的变化

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写或保留问题提示 | `problem` · 当前情况与希望弄清的问题 | 说明当前事实与未知、希望回答的问题，以及结论将支持什么判断。 |
| 去除旧方法要求 | `evidence_plan`、`stop_rule` | 移除预设的方法、比较与证据计划块。原结束条件中真实的研究边界和投入约束归 scope，结论应回答什么及允许的不确定范围归 acceptance；不让制定者先设计实验、样本或资料路线。 |
| 沿用共同字段 | 除 problem 外八项共同字段 | 按共通决定表达领域、责任、要求与实际进展，不换名加入方法要求 |

完整表单共 9 个输入块。标题前缀、保留字段的 ID 和交付物选项继续沿用；历史 Issue 不批量回写。

### 完成条件

研究结论可以支持、不支持或在明确范围内仍不确定。验收检查问题是否得到有依据的回答、证据能支持什么、限制是否清楚；预算耗尽或缺少关键依据不能直接算完成。必要的比较与证据属于最终成果质量，取得它们的方法由负责人负责。仅交正式决定时，其正文仍须足以支持结论；不把完成研究当成产品能力已实现。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 用功能模板验收能力可用 | 方便接实现 | 把未知答案预定为成功 | 研究按有依据的结论验收 |
| 只写调研名称或报告路径 | 建项快 | 范围与结论用途不清 | 主表明确问题、用途与结果边界 |
| 固定方法、时间与样本 | 形式可比较 | 资料核对与实验需求不同，限制探索 | 只保留真实约束，不规定通用路线 |
| 方法与停止条件独立成块 | 旧版便于限定取证和投入 | 要求制定者过早完成研究设计 | 移除两块，保留问题边界与结论质量 |

## 影响与验证

同步当前表单、共通说明与差异索引；核对输入块数、问题职责、方法要求的移除和实际需求的去向。主 Issue 填写案例应能在不知道实现方法时表达完整需求；子项不提供示范正文。#6 旧版的演练和线上检查保留为历史，本轮结果及未覆盖范围见 [本轮验证](../../../../docs/validation/2026-09-10-main-issue-templates.md)。

## 重开条件

真实主 Issue 反复遗漏必要事实、成果质量或边界，或共同提示造成无法表达的需求时，带实例修订原决定。子项是否提炼模板依据共通决定中的实践条件，不因主表更新自动推广。
