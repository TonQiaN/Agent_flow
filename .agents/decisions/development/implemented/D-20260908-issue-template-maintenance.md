# 维护模板补充改动、兼容与验证计划

创建于 2026-09-08。

## 结论与边界

维护模板用于落实工程、文档、配置或协作改进，目标文件为 `.github/ISSUE_TEMPLATE/maintenance.yml`，前缀为 `[维护]`。本决定负责相对 [共通规范](../README.md#d-20260908-issue-template-common) 的差异；具体归类按 [分类决定](../README.md#d-20260908-issue-classification) 判断，不能仅凭文件名、代码行数或“不面向用户”认定轻量。

### 相对共同基线的增删改

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写 | `problem`：当前问题与工程目标 | textarea，创建必填。说明当前工程或协作问题、维护原因，以及本次要落实的可观察结果 |
| 增加 | `change_plan`：改动、兼容与验证计划 | textarea，创建必填。列受影响入口与差异、保留契约、适用迁移/回退及验证；无迁移的文字修订可说明不适用，不写空泛回滚手册 |
| 删除 | 无 | 维护同样需要主责、明确边界、交付物及验收；不因“只是文档”删除决定与交接职责 |
| 保留并解释 | `acceptance` 等其余七字段 | 验实际文件、约定行为及验证结果；若已承诺模板/指南，不能凭研究报告或决定替代这些交付 |

完整表单共九个输入块；change_plan 放在 problem 后。必要研究和方案讨论可以是维护工作的一部分，最终仍以工程目标验收。版本规划和 CHANGELOG 的维护时点沿用 [版本管理决定](../README.md#d-20260908-version-management)，不在所有维护 Issue 中新增发版审批或固定版本号字段。

### 条件信息与验收

升级依赖时说明相关版本与兼容验证；重构时说明需要保持的契约；迁移数据时说明旧样本与适用失败/回退方式；改模板和开发指令时说明入口、字段/规则映射及使用者如何接续。各项按实际任务填写，不把所有条件拆成所有维护事项的强制字段。

维护也可能产生新的产品行为或恢复既有失败契约，遇到这类目标按分类决定选择功能或缺陷。既有契约内改善工程结构可归维护；未知瓶颈的独立调查可归研究，不能用维护标签掩盖未定范围。

Issue #6 的整体目标是分类、正式决定、实际模板与使用指南：本轮写出七份决定完成其中一部分，后续仍需五类表单、说明、适当验证及默认分支核对。填写验收时应保留这些交付，不因进入研究阶段更换类型或缩成“决定写完即可关闭”。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 将维护作为所有未归类工作的兜底 | 不必新增入口 | 研究、选择与工程交付混杂，完成条件不明 | 维护聚焦实际工程结果，其他按五类边界选择 |
| 只填写共通目标与验收 | 适合很小的文档事项 | 容易漏掉影响入口、保留契约与迁移方式 | 补一个可简写的 change_plan |
| 文档、重构、升级、测试、发布各建专类 | 提示更专门 | 当前共享主责与交付规则多，模板数量增长快 | 通过任务相关条件填写，不预先拆类 |
| 强制每项都填完整回退与产品测试 | 检查表整齐 | 文字修订产生大量无意义内容和虚假测试记录 | 按影响选择必要验证，不适用如实说明 |

## 影响与验证

保留 maintenance.yml 路径和旧共同 ID，增加 change_plan、共同交付物和续接字段；核对九字段和基线一致性。用 Issue #6 模板治理、一个无数据迁移的指南修订、一个假设依赖升级分别填写，检查能否兼顾文件交付和适用兼容信息；不为样例执行升级或发布。

模板与使用指南已落实，默认分支选择器及实际表单展示已核对，结果见实施验证。本轮文本核对见 [设计验证记录](../../../../docs/validation/2026-09-08-issue-template-decisions.md)。

## 重开条件

维护类持续成为模糊工作集合、同一种工程事项反复缺关键验证信息，或 change_plan 与 scope/acceptance 大量重复时，用真实例子调整提示或字段。拆出专类需回到分类决定说明独立完成条件。
