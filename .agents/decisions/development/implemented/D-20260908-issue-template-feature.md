# 功能主 Issue 说明当前场景与期望能力

创建于 2026-09-08。

## 结论与边界

本决定负责 `.github/ISSUE_TEMPLATE/feature.yml` 相对 [主 Issue 共通规范](../README.md#d-20260908-issue-template-common) 的差异。表单帮助制定者表达需求，执行方案由对应负责人负责；本决定的字段约束仅适用于主 Issue。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的变化

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写或保留问题提示 | `problem` · 当前场景与期望能力 | 说明谁在什么场景遇到什么限制，希望新增或改变什么能力。 |
| 去除旧方法要求 | `behavior_contract` | 输入输出和正常／边界／失败结果并入 problem 与 acceptance；已有兼容、权限或副作用约束及依据放在 scope。主表不预先规定内部接口或结构。 |
| 沿用共同字段 | 除 problem 外八项共同字段 | 按共通决定表达领域、责任、要求与实际进展，不换名加入方法要求 |

完整表单共 9 个输入块。标题前缀、保留字段的 ID 和交付物选项继续沿用；历史 Issue 不批量回写。

### 完成条件

功能验收核对用户可观察的结果和必要边界；实际验证由负责人根据工作确定。回放类主 Issue 可以描述“停在结果返回前不显示未来输出”，无须先规定存储、渲染或时序实现。这是需求示例，产品尚未实现。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 只用目标与验收 | 字段少 | 旧版担心遗漏行为边界 | 本轮改写提示以保留结果与边界 |
| 场景外增加行为契约块 | 过去便于集中输入输出 | 与问题和验收重复，也容易提前写内部设计 | 移除独立块，实际要求融入共同字段 |
| 把接口、权限、兼容分别设字段 | 大功能覆盖细 | 小任务出现大量不适用项 | 按真实需求表达在共同范围与结果中 |
| 建项时强制完整技术方案 | 看似便于编码 | 过早锁定实现并增加需求制定者负担 | 不采用 |

## 影响与验证

同步当前表单、共通说明与差异索引；核对输入块数、问题职责、方法要求的移除和实际需求的去向。主 Issue 填写案例应能在不知道实现方法时表达完整需求；子项不提供示范正文。#6 旧版的演练和线上检查保留为历史，本轮结果及未覆盖范围见 [本轮验证](../../../../docs/validation/2026-09-10-main-issue-templates.md)。

## 重开条件

真实主 Issue 反复遗漏必要事实、成果质量或边界，或共同提示造成无法表达的需求时，带实例修订原决定。子项是否提炼模板依据共通决定中的实践条件，不因主表更新自动推广。
