# 决策模板补充真实比较与落实交接

创建于 2026-09-08。

## 结论与边界

决策模板用于有主责、明确选择问题和结束条件的方案讨论，目标文件为 `.github/ISSUE_TEMPLATE/decision.yml`，前缀为 `[决策]`。它描述该工作项需要作出的选择，不替代正式决策正文的 [内容规范](../README.md#d-20260907-decision-record-content)；两者之间是讨论与浓缩决定的关系。模板继承 [共通规范](../README.md#d-20260908-issue-template-common)，选类按 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的增删改

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 改写 | `problem`：需要敲定的问题与适用范围 | textarea，创建必填。说明为何现在要选择、影响谁、哪些约束已有确认、本次仍要选择什么；已有用户确认不重复列为未决项 |
| 增加 | `options`：候选方案与比较依据 | textarea，创建必填。比较实际候选、收益、代价、维持现状的后果和证据限度，推荐尚未确认时如实标识 |
| 增加 | `impact`：影响、落实与重开条件 | textarea，创建必填。描述接口/文档/流程影响、保留边界、后续实施去向、仍需证据及什么新事实值得重开 |
| 删除 | 无 | 只交决定也需要交付定义、验收、主责和依赖，不能用“讨论”省去结束条件 |
| 保留并解释 | `acceptance` 等其余七字段 | 验自足结论、真实比较、范围确认和必要交接；不把采纳等同于实现，也不自动要求产品运行测试 |

完整表单共十个输入块；problem 后放 options、impact。options 没有候选数量配额；只有一种合理方案时说明原因，不编造稻草人方案或实验结果。已知否决理由优先引用现行正文，不因工具换名反复重开同一问题。

### 仅决定交付的验收

若范围仅为 high level 确认或方案选择，可以只交付正式决定。验收检查：结论与边界自足，实际比较和理由清楚，必要未知已解决或有不影响当前选择的有限交接，主责对具体范围的确认可核对。确认依据可以是已有明确用户指令，不增加固定审批人数。

如果选择依赖尚缺的关键事实，先明确所需证据或有界取舍；不能靠填写“推荐方案”表示问题已敲定。方案采纳但未实施时写清后续归属和未实现部分，正式决定的目录按 [生命周期](../README.md#d-20260907-decision-lifecycle) 判断，不因决策类 Issue 关闭机械移动到 implemented。

例如敲定首个可用切片的 high level 验收：保留前端只读、外围回放、镜像/节点能力分层、三 Harness 模块化等已明确边界，比较首批能力组合与交付切片。形成决定可完成这个选择任务，但不能据此宣称前端或 Harness 已存在。若同项还承诺模板或代码，仍需完成这些交付；Issue #6 属于此种有文件实施要求的维护工作。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 沿用研究模板，要求证据实验与停止预算 | 有明确探索边界 | 纯范围选择未必需要实验，容易假造研究步骤 | 决策专用比较与落实字段；必要研究仍可同项进行 |
| 只写推荐方案，正文直接结束 | 简短、推进快 | 未选理由和影响丢失，容易重复讨论 | 保留真实比较与交接 |
| 要求每次至少三个方案、多名批准人 | 形式整齐，鼓励讨论 | 虚构比较并增加启动期等待，不符合现有确认方式 | 无数量门槛，保留实际审阅事实 |
| 比较 options，落实 impact，正式决定浓缩结论 | 选择理由和后续责任可分别核对 | 需避免把全部讨论搬入决定 | 采用，沿用一问题一正文 |

## 影响与验证

新增决策表单，核对十字段与共通规范。用仅决定的 high level 确认例验证：能保留已确认约束、真实比较、尚未实施事实和具体结束条件；再用“仍缺关键证据”和“已承诺实现文件”的反例确认不能提前验收。正式决定按内容规范自足，模板只帮助收集讨论输入。

本轮文本核对见 [设计验证记录](../../../../docs/validation/2026-09-08-issue-template-decisions.md)，新表单已完成本地填写核对，线上入口已在默认分支实际核对。

## 重开条件

出现决策与研究持续难以区分、同一理由在 Issue 与决定中独立维护失配、已确认约束反复被重开，或“决定完成”被误用为产品实现时，带实例修订字段与完成解释。
