# 缺陷主 Issue 保留行为差异、复现与环境

创建于 2026-09-08。

## 结论与边界

本决定负责 `.github/ISSUE_TEMPLATE/bug.yml` 相对 [主 Issue 共通规范](../README.md#d-20260908-issue-template-common) 的差异。表单帮助制定者表达需求，执行方案由对应负责人负责；本决定的字段约束仅适用于主 Issue。类型选择见 [分类决定](../README.md#d-20260908-issue-classification)。

### 相对共同基线的变化

| 操作 | 字段 | 内容与取舍 |
| --- | --- | --- |
| 保留问题提示 | `problem` · 实际与期望行为 | 区分触发条件、观察结果、期望及其现行依据，根因猜测不冒充事实。 |
| 保留事实职责 | `reproduction`、`environment` | 保留 reproduction（复现步骤与已有证据）和 environment（版本与相关运行条件），均为问题事实，不能当作修复方法删去。两块跟在 problem 后；其余字段沿用新的主 Issue 共通基线。 |
| 沿用共同字段 | 除 problem 外八项共同字段 | 按共通决定表达领域、责任、要求与实际进展，不换名加入方法要求 |

完整表单共 11 个输入块。标题前缀、保留字段的 ID 和交付物选项继续沿用；历史 Issue 不批量回写。既有 Bug behavior→problem 迁移保留。

### 完成条件

允许根因未知或尚未复现的缺陷，记录实际尝试与缺少条件，预检由负责人判断补证或处置。相关运行条件按问题选择，可包含 Harness、镜像、节点能力与外围输入输出，不强制全量工具或 agent 内部轨迹。实际修复需恢复既有行为并核对相关回归，不能把补证或研究完成当成修复。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 只留问题与验收 | 表单短 | 缺少复现和相关环境会反复追问 | 继续保留两块事实字段 |
| 已复现且已知根因才建项 | 输入看似直接可用 | 丢失间歇故障与外部报告，容易编造原因 | 允许未知并如实跟进 |
| 保留旧 behavior 作为例外 | 少改旧 ID | 与共同 problem 同义，长期核对多一别名 | 沿用 #6 已完成的统一迁移 |
| 并列 behavior 与 problem | 旧字段仍在 | 同一事实重复，可能相互矛盾 | 只保留 problem |
| 全量环境与内部 agent 日志必填 | 资料可能充分 | 无关负担大，超出外围记录边界 | 只收问题事实，不规定修复方法 |

## 影响与验证

同步当前表单、共通说明与差异索引；逐对象核对 problem、reproduction、environment 与 #6 基线一致，并核对本轮共同字段。主 Issue 填写案例应能在不知道实现方法时表达完整需求；子项不提供示范正文。#6 旧版的演练和线上检查保留为历史，本轮结果及未覆盖范围见 [本轮验证](../../../../docs/validation/2026-09-10-main-issue-templates.md)。

## 重开条件

真实主 Issue 反复遗漏必要事实、成果质量或边界，或共同提示造成无法表达的需求时，带实例修订原决定。子项是否提炼模板依据共通决定中的实践条件，不因主表更新自动推广。
