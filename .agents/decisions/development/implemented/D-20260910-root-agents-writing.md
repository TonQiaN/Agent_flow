# 根目录 AGENTS.md 作为简短的项目工作入口

创建于 2026-09-10。

## 结论与边界

根目录 AGENTS.md 面向进入仓库的开发代理，承担全项目入口职责，使用独立书写决定。本决定仅管理下列指令正文；其他目录的 AGENTS.md 沿用各自唯一负责决定。

| 受管文件 | 作用范围 | 书写职责 |
| --- | --- | --- |
| [根 AGENTS.md](../../../../AGENTS.md) | 整个项目 | 必要规则、真实仓库布局、按任务读取的 docs 入口、团队约定 |

根文件的归属从 [D-20260907-agents-writing](../README.md#d-20260907-agents-writing) 完整迁移到本决定，原决定继续负责决策目录 AGENTS.md。一次迁移同步双方清单和根文件回链，同一文件不增加共同负责决定。

### 简短、准确、具体

根文件保留实际影响工作方式的必要指令、可定位的项目事实和文档入口。使用短句说明适用情形与动作；详细操作放在 docs，取舍理由留在决定。根据重复错误、审查反馈和项目发展修订，不预先堆积缺少实际依据的规则。

这一写法采用 OpenAI 的 [AGENTS.md 最佳实践](https://learn.chatgpt.com/guides/best-practices#make-guidance-reusable-with-agentsmd) 和 [项目指引维护建议](https://learn.chatgpt.com/docs/customization/overview#agents-guidance)，于 2026-09-10 核对。官方建议支持精简、具体、按范围组织和反馈驱动维护；独立书写决定及下述符号链接约定来自本次用户确认。

### 第一项必要规则：共享同一份项目指令

项目内每份 AGENTS.md 都须有同目录的 `CLAUDE.md -> AGENTS.md` 相对符号链接。新增、移动或删除指令文件时同步维护对应链接，不能用两份复制正文代替。现有根目录链接保留，并为决策目录补齐链接。

该约定让 Claude 与 Codex 的仓库指令入口指向同一份正文。它保证文件内容一致；工具各自的全局配置、权限和实际加载行为仍需分别核对，不能从符号链接推导出完整运行配置或执行效果相同。

### 仓库布局及更新

根文件提供路径与职责对应的简短布局，包含实际存在的指令、决策、模板、docs 和原始资料区。布局随目录结构、职责和开发入口变化在对应改动中更新；完整结构说明继续放在 `docs/reference/repository-map.md`。

布局按职责采用不同粒度：`src/` 展开实际代码导航所需的应用、包、测试、示例与工具；其他目录只列根级入口和职责，例如 `.agents/`、`.github/`、`docs/` 与 `materials/`。非源码目录后续会分别设计 AGENTS.md，内部细节由各目录指令承担；src 不一定设置局部 AGENTS.md，因此根入口保留足够的代码地图。本次仅调整根布局，后续目录指令另行设计；docs 中的完整结构图保留其参考所需的细节。

当前已实现能力与未完成范围通过 docs 文档入口定位，根文件不重复维护一套阶段结论。已有产品实现时，布局列出真实的 src、应用、包、测试和工程入口；入口尚未建立时，才用标注“待确定、尚未创建”的占位表达未来位置，落地后及时替换。截图仅作为路径与职责的呈现参考，其模块名不构成本项目的目录或架构选择。

### 通过 docs 引用工作说明

根文件按实际任务链接到项目文档入口、开发工作指南、Issue 填写、文档维护和版本维护说明。若适合指引开发的操作内容只有决定中的论述，先把已确认、当前适用的部分写入对应 docs，标清尚未实现的能力，再从根文件引用；取舍和否决理由继续留在决定中。

项目概览的读取条件是需要确认当前能力、未完成范围或查找文档入口。已定位的错字、链接或其他局部任务直接按任务读取相关说明，不再把概览设为所有工作的前置步骤。该调整依据 [Issue #20 的指令审查](../../../../docs/validation/2026-09-14-agent-instructions-audit.md) 中 R1 的文本问题，并参考用户指定的 [OpenAI 文章](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 关于任务相关阅读的建议；不取消真正适用的目录指令或开发要求。

已有 Issue 开工、预检、PR 实质决策改动与验收规则由 `docs/development/workflow.md` 说明，主／子 Issue 分工由 `docs/development/issue-templates.md` 说明，指令维护由 `docs/development/documentation.md` 说明，版本维护由 `docs/development/versioning.md` 说明。根入口保持这些规则的执行入口，不复制完整流程，也不改变已确认的开发门槛。

产品实现开始后，[源码结构决定](../README.md#d-20260909-source-layout) 中已适用于开发的目录职责、公共导入边界、TypeScript 工作区与验证命令，整理为 `docs/development/code-structure.md` 后供根入口引用；目录选择与替代方案的理由仍由源码结构决定负责。运行入口链接到 `docs/guides/README.md`。这延续了产品基础切片中以 docs 维护当前能力的选择。

根文件保留指向本唯一书写决定的回链；编辑决策区前，仍明确要求读取该目录 AGENTS.md。后者是局部指令入口：[Codex 官方加载说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance)指出启动发现沿根目录到当前工作目录展开，不能假定从根目录启动已自动读取所有子目录。

### 团队约定

根文件集中提示当前已确认的共同约定：正式开发有 Issue、明确的人类主责及人参与的关键确认；按已确认范围执行，已有授权不重复请求；主 Issue 说明整体需求，Sub-issue 由负责人自主组织；决定、当前说明、规划与原始资料各守其边界；按实际成果记录验证和完成情况。具体流程通过上述 docs 查阅，不借此次精简新增审批或更改交付门槛。

materials 建立局部指令后，根文件将默认不读、不搜索的边界明确限定为原始内容，并链接局部 AGENTS.md。团队共享资料使用飞书 CLI 的 AgentFlow 配置，在已核实的 AgentFlow 组织中管理；根入口只提示共同选择并引用 docs 操作说明，避免依赖机器当前默认 profile。保存与共享取舍由 [materials 决定](../README.md#d-20260911-materials-management) 提供依据，不改变根文件的唯一书写归属。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 根入口使用独立书写决定 | 根目录的全项目职责和后续变化可独立理解 | 迁移时需同步原负责清单与回链 | 按用户确认采用；原合管方案的历史保留在原决定 |
| 根入口保留完整流程与论证 | 单文件可读到全部细节 | 每个任务都承担无关内容，且容易与指南重复 | 采用短指令和 docs 链接，决定保留理由 |
| 所有任务先读项目概览 | 统一从能力事实入口开始 | 已定位的小改动也承担无关阅读，与按任务导航的目标不符 | 2026-09-14 改为需要判断能力、范围或寻找入口时读取；现有任务入口继续适用 |
| 资料共享约定只出现在 materials 内 | 局部说明集中 | 从其他任务产出的 artifact 也可能值得团队共享，仅局部入口容易漏读 | 根入口保留飞书 CLI 的共同选择，具体操作和核对放入 docs |
| 根布局统一展开源码与非源码目录 | 首版可直接看到各目录内部入口 | 增加根入口负担，并提前承担后续各目录 AGENTS.md 的细节职责 | 2026-09-11 按用户修订改为只展开 src，其余目录列根级入口与职责 |
| AGENTS.md 与 CLAUDE.md 分别维护正文 | 可分别编辑 | 两份相同项目规则容易漂移 | 同目录相对符号链接，共用正文 |
| 布局中列出尚未建立的产品路径 | 可以展示未来入口 | 容易被误认作已存在或已选定的架构 | 保留真实布局，未建立部分用明确占位说明 |
