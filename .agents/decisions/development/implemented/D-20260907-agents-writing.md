# 决策目录 AGENTS.md 的职责与唯一书写归属

创建于 2026-09-07。

## 结论与边界

项目内每份 AGENTS.md 的书写、职责和变更理由都由唯一一项书写决策完整负责。一项决定可以管理一份或多份 AGENTS.md，同一份 AGENTS.md 不能由多项书写决策共同管理。文件声明自己的唯一书写决策，决定列明其管理的完整文件集合。

本决定当前仅管理下列文件；此表是对应关系的主记录，文件内的回链用于反向定位。2026-09-10 按用户确认将根 AGENTS.md 的完整归属迁移至 [D-20260910-root-agents-writing](../README.md#d-20260910-root-agents-writing)，本决定不再负责根文件书写。

| 受管文件 | 作用范围 | 当前书写职责 |
| --- | --- | --- |
| [决策 AGENTS.md](../../AGENTS.md) | .agents/decisions 及其子目录 | 决策查重与提炼、生命周期转换、索引维护、真实确认与审阅记录、PR 中的决策检查，以及决策系统自身的书写纪律 |

决策目录的 CLAUDE.md 按根入口要求，以同目录相对符号链接复用本目录 AGENTS.md，正文仍由本决定唯一负责。未来新增 AGENTS.md 时，先确定唯一归属；职责相关时扩展既有决定，确属独立范围时才建立新的书写决定。修改既有文件回到其原负责决定，不能因为多改一次就增加一个共同负责人。普通错字修正仍沿用既有决定，无需制造新的取舍记录。

## AGENTS.md 与 README.md 的分工

本目录 AGENTS.md 保存决策编辑的执行指令，包含作用范围、读取顺序和必要约束；README.md 说明目录内容并提供导航，不另行维护一套执行规则。该目录的书写理由集中在本决定中，详细操作说明放在 docs，原始讨论不进入 AGENTS.md。根入口的布局、docs 引用和团队约定由根入口独立决定管理。

生命周期、唯一正文与 alternatives 等决策编辑细则放在本目录 AGENTS.md；README 保留分类、索引、模板与维护入口。局部细则只在决策工作中读取，减少普通任务的上下文负担和重复规则。

本目录 AGENTS.md 按需引用生命周期、内容和开发流程决定以定位规则依据。被引用决定管理其自身问题，不因此共同管理本目录指令的书写。若领域事实变化需要修改该文件，在本决定里记录如何调整，再同步正文。

本目录保留按 [开发流程决定](../README.md#d-20260907-development-workflow) 核对实际决策正文增量的指令，防止把引用 ID 或只改索引当作满足 PR 门槛。先写文档不要求先独立提交或合并，指令不能自行增加审批阻塞。整理阶段允许 AI 和工具协助提炼，人参与关键澄清与确认，不能将人的参与误写为全程手工作业。

Issue 承接审查确认后，本目录入口按明确确认依据判断实施范围；proposed 表达尚未全部落实，不能一概写成“未采纳”，也不能把目录本身当作授权。入口要求浓缩确认摘要并定位 Issue；详细讨论及审阅过程归 Issue，指令不新增等价审批状态。

原根入口中的版本维护、Issue 开工和知识边界提示已归入根入口独立决定；相关操作继续由 docs 中的工作指南、文档维护和版本维护说明承载。此前调整的确认记录保留在本文件历史中。

## 指令加载与作用范围

核对的 Codex 行为是：启动时从项目根目录沿路径加载至当前工作目录，更靠近当前目录的项目指令出现在后面；不会为了根目录任务自动遍历所有子目录。本目录指令因此仍需由根入口显式引导读取；该根入口写法由其独立决定负责，不能只依赖目录名推测本文件已自动加载。README.md 在此项目中承担导航职责。

这里的目录内细化只作用于相应范围，不将子目录约定写成全项目覆盖。本轮补齐同目录指令链接，其他工具的实际加载行为仍需分别验证。技术依据：[OpenAI 官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，2026-09-10 核对。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 决策编辑细则放本目录 AGENTS.md，README 专注导航 | 按范围执行，规则可定位 | 需要根入口引导读取局部规则 | 采用 |
| 所有决策细则与理由都写入根 AGENTS.md | 单入口直达 | 普通任务也承担决策编辑细节与论证的阅读成本 | 编辑细则按目录组织，理由留在决定 |
| 仅 README 保存决策操作约束 | 一般文档阅读方便 | 不能据此保证工具按专门指令文件加载，容易漏读 | 不作为本目录执行规则主文 |
| 根与决策目录 AGENTS.md 共用一项书写决定 | 启动期便于统一解释两个相互配合的入口 | 根目录承担全项目入口，后续演进与局部决策编辑职责不同 | 曾采用；2026-09-10 按用户确认拆出根入口，本决定只负责决策目录 |
| 多项决定共同管理同一 AGENTS.md | 各个局部取舍容易另起笔记 | 理由分散，修改时必须拼接多个管理来源 | 按用户要求不采用，一份文件只有一个负责决定 |
| 在本目录 AGENTS.md 展开全部 Issue / PR 细节 | 编辑决定时可同时看到完整流程 | 重复工作指南和领域决定，降低局部指令密度 | 只提示与决策编辑有关的检查，引用相关依据 |
