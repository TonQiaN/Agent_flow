# AGENTS.md 的职责分层与唯一书写决策

创建于 2026-09-07。

## 结论与边界

项目内每份 AGENTS.md 的书写、职责和变更理由都由唯一一项书写决策完整负责。一项决定可以管理一份或多份 AGENTS.md，同一份 AGENTS.md 不能由多项书写决策共同管理。文件声明自己的唯一书写决策，决定列明其管理的完整文件集合。

本决定管理下列两份文件，并解释当前全部职责分工；此表是对应关系的主记录，文件内的回链用于反向定位。

| 受管文件 | 作用范围 | 当前书写职责 |
| --- | --- | --- |
| [根 AGENTS.md](../../../../AGENTS.md) | 整个项目 | 项目阶段、知识边界、按任务读取入口、Issue 归属与开工条件、文档先行及 PR 决策改动入口、编辑任一 AGENTS.md 的唯一归属要求 |
| [决策 AGENTS.md](../../AGENTS.md) | .agents/decisions 及其子目录 | 决策查重与提炼、生命周期转换、索引维护、真实确认与审阅记录、PR 中的决策检查，以及决策系统自身的书写纪律 |

根目录 CLAUDE.md 仍是 AGENTS.md 的符号链接，同一正文沿用同一书写决策，不单独建立另一套理由。未来新增 AGENTS.md 时，先确定唯一归属；职责相关时扩展既有决定，确属独立范围时才建立新的书写决定。修改既有文件回到其原负责决定，不能因为多改一次就增加一个共同负责人。普通错字修正仍沿用既有决定，无需制造新的取舍记录。

## AGENTS.md 与 README.md 的分工

AGENTS.md 保存需要代理执行的简短指令，包含作用范围、读取顺序和必要约束；README.md 说明目录内容并提供导航，不另行维护一套执行规则。为什么这样分工、为什么写这些规则，集中在本决定中。详细操作说明放在 docs，原始讨论不进入 AGENTS.md。

根入口保留所有任务都需要的约束，把生命周期、唯一正文与 alternatives 等决策编辑细则放入决策目录 AGENTS.md；README 保留分类、索引、模板与维护入口。这样既能使用指令文件的专门加载机制，也减少普通任务的上下文负担和重复规则。

AGENTS.md 中可以按需引用产品决定或开发流程决定以定位领域事实。被引用决定管理其自身问题，不因此共同管理这份 AGENTS.md 的书写。若领域事实变化需要修改 AGENTS.md，在本文件的唯一负责决定里记录如何调整指令，再同步正文。

本次将根入口中的“已有决定覆盖时引用”调整为按 [开发流程决定](../README.md#d-20260907-development-workflow) 执行：用简短指令连接 Issue、人参与整理、预检、文档先行和每个 PR 的决策改动检查。它们影响所有正式开发，故保留根入口提示；字段、阶段细节和理由通过链接读取。决策目录入口补充实际正文增量检查，防止把引用 ID 或只改索引当作满足 PR 门槛。先写文档不要求先独立提交或合并，指令不能自行增加审批阻塞。整理阶段允许 AI 和工具协助提炼，人参与关键澄清与确认；根入口明确这一分工，避免将人的参与误写为全程手工作业。

Issue 承接审查确认后，两份入口都改为按明确确认依据判断实施范围；proposed 表达尚未全部落实，不能再一概写成“未采纳”，也不能把目录本身当作授权。根入口提示此区别，决策目录入口要求浓缩确认摘要并定位 Issue；详细讨论及审阅过程归 Issue，指令不新增等价审批状态。这些调整仍由本唯一书写决定负责。

## 指令加载与作用范围

核对的 Codex 行为是：启动时从项目根目录沿路径加载至当前工作目录，更靠近当前目录的项目指令出现在后面；不会为了根目录任务自动遍历所有子目录。因此根 AGENTS.md 显式要求，在创建或修改决策正文、模板、目录与索引前读取决策 AGENTS.md，不能只依赖目录名推测它已自动加载。README.md 在此项目中承担导航职责。

这里的目录内细化只作用于相应范围，不将子目录约定写成全项目覆盖。其他 Harness 的实际加载行为需要分别验证；本轮未修改其配置。技术依据：[OpenAI 官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，2026-09-07 核对。

## 方案考量（alternatives）

| 方案 | 可取之处 | 代价或不适用原因 | 本次取舍 |
| --- | --- | --- | --- |
| 根指令加目录内指令，README 专注导航 | 按范围执行，入口短，规则可定位 | 根入口需要显式引导读取嵌套规则 | 采用 |
| 所有细则与理由都写入根 AGENTS.md | 单入口直达 | 每项任务都承担决策编辑细节与论证的上下文成本 | 细则按目录分工，理由留在决定 |
| 仅 README 保存操作约束 | 一般文档阅读方便 | 不能据此保证工具按专门指令文件加载，容易漏读 | 不作为执行规则主文 |
| 每份 AGENTS.md 各自一项书写决定 | 范围清晰 | 当前两份相互配合的入口会拆散同一设计问题 | 当前一项决定管理两份，未来独立范围可单独负责 |
| 多项决定共同管理同一 AGENTS.md | 各个局部取舍容易另起笔记 | 理由分散，修改时必须拼接多个管理来源 | 按用户要求不采用，一份文件只有一个负责决定 |
| 在根 AGENTS.md 展开全部 Issue / PR 细节 | 每次加载都能看到完整流程 | 重复工作指南和领域决定，降低日常读取密度 | 仅保留执行入口与关键约束，通过链接定位细节 |

## 重开条件

出现独立模块专门指令需求，或一项书写决定过大而难以共同维护时，按完整文件集合拆分职责；迁移归属必须同步移除旧对应关系，仍保持每份文件只有一个负责决定。工具加载行为变化时再调整读取入口。
